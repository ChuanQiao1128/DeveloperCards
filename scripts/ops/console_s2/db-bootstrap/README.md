# Fixed owner database prerequisite helper

This package runs only as an unaliased numeric version of the isolated core clone, before its ordinary runtime alias is created. No production function, API alias or environment receives the helper. Its execution role has VPC/log access and no Secrets Manager permission. The owner reads the exact RDS-managed secret in memory and passes its password transiently through direct IAM Invoke. Request bodies, credentials and raw exceptions must never be retained in evidence or logs.

Public configuration: S2_RUN_ID, S2_MANIFEST_SHA256, S2_PRODUCTION_DATABASE, S2_EXPIRES_AT and verified PG host/port/TLS. The helper derives the only isolated database and role names from the frozen run ID; there is no SQL, host or database field in the request. Every operation validates the function name, numeric invocation, run ID and manifest identity. Provision and inspection stop at the finite expiry; owned teardown remains possible afterward.

Fixed operations audit production catalog ACLs, provision the dedicated production SELECT-only observer, create the isolated database/login, apply the embedded frozen migrations only in that owned database, provision its observer, run the exact observer EXPLAIN, hold one isolated fixture lock for45or10seconds, and drop the owned isolated database/roles. They never modify production learner or content rows. Unsafe PUBLIC access in every non-system schema stops provisioning. Effective role table/column (including PostgreSQL17 MAINTAIN), sequence, definer-function and schema-CREATE privileges are checked separately. All fixed data targets are public-qualified and each session pins search_path=public. Observer logins have connection limit2; isolated runtime limit6. Ownership comments and exact database owners support reconciliation after an uncertain create response. The production observer survives isolated cleanup.

The isolated runtime login owns only its fresh database, matching production legacy mode. It has no role membership/admin attributes and its effective production table privileges are checked. Production056 grants to the globally named app role are explicitly revoked inside the isolated database after migration. Production database mode/grants remain untouched.

Local checks use a uniquely owned PostgreSQL17 container. Run tests/DbBootstrapChecks.csproj with S2_TEST_CONNECTION pointing to loopback only; the assertions exercise unsafe PUBLIC data/definer ACLs, cross-database denial, SELECT-only observer behavior, migration replay, exact EXPLAIN and owned teardown, all-absent response-loss replay and cross-schema/shadow-path attacks. Local results do not establish production ACLs, RDS capabilities, cleanup or query performance.
