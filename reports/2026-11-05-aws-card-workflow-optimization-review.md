# 制卡流程优化与独立审查

日期：2026-11-05。范围：修改本地制作流程并验证；未制作新卡、未修改当前卡文或发布。

## 已接入的流程

本地文件预检 → 5–10张同次写作并检查歧义 → 一份冻结输入独立审卡及题目支撑 → 仅修失败及受影响项 → 本地导出、累计清单和索引收尾。

1. **提前检查歧义。** 作者同次检查题面允许的反例，包括共用路由表、直接连接或经过ALB、同/跨Region、发起方和接收方；检查必答是否超出题面。必要术语通过请求路径解释。该提示不能代替独立审查。
2. **合并审查交接。** 正式新批次启用`checkQuestions: true`；完整题干、全部选项、已有条件/必要判断/异常，与当前卡和必要官方摘录一起冻结。去掉历史PASS叙述及机械元数据，不重复提炼考点。七项知识卡审查与逐题支撑分别输出，partial/unknown不升级。
3. **局部修正与凭证复用。** 自动生成供主Agent使用的修正交接单；Reviewer不接收作者历史或旧结论。卡、来源、评分、标准、规则或递归先修变化时，只重审受影响卡和题目；有效单题补审可在后续修正中继续复用。缓存按请求去重验证，不再按每张卡重复解析同一报告。
4. **自动累计收尾。** 沿用`pipeline.py`入口，由新增`closeout.py`合并接受清单、区分新增/修订/复用、合并题卡状态、刷新既有领域索引并生成摘要。无需手写一轮长JSON或另建数据库。
5. **校验后更新当前指针。** 卡片写入版本目录，真实Linter和导入回读通过后才选为交付。全部收尾预检通过，再在共享runtime文件锁中重新比较完整run哈希、原子替换并回读当前索引。中断与重复运行均保留原时钟、失败证据和修复历史，不重置预算。

新作者入口拒绝缺少原题检查或累计收尾的配置；`replayOnly: true`明确禁止派作者。旧回放配置继续可读，但其本地完成不能替代新的逐题支撑验收。

## Review发现与修正

| 发现 | 已采取的修正 |
| --- | --- |
| 原审卡包不含原题，不能执行同次题卡核查 | 接入题干、全部选项和既有需求，逐题逐判断记录卡文锚点与缺口 |
| 首稿歧义在送审后才暴露 | 同次写作增加合法反例及必答范围检查，保留独立审查 |
| 局部修正可能重复处理已有效内容 | 逐卡/递归依赖完整指纹；逐题按相关依赖复用，补审子集可继续沿用 |
| 就地覆盖交付可能留下旧complete | 版本化产物；开工先使旧当前完成状态失效；失败写failed，旧完成时间保留为历史 |
| 累计UID、索引和运行指针需手工衔接 | 自动合并、计数和刷新引用；校验后更新指针 |
| 比较哈希与替换之间可并发丢更新（WFO-CAS-001） | 共享文件锁内重新比较、替换、回读与记录提交；有跨进程回归 |
| 分类CSV等到收尾才发现不可读 | 15秒预检包含索引manifest引用的来源与分类CSV；未就绪先停 |

独立审查最终结论为 **PASS，剩余阻断项0**。记录保留在运行目录的`independent-review.json`，绑定实际代码与冻结输入；WFO-CAS-001保留首次FAIL及修复闭合证据。
