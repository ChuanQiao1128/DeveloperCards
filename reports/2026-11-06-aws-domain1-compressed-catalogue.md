## 1. 私网实例通过SSM身份建立管理会话 · CA03

**问：** 管理员要进入私网EC2，不想分发共享SSH密钥或维护跳板机。SSM Agent已安装且能连接服务，还应怎样让实例接入并管理？

**答：** 给实例关联具备SSM所需权限的实例角色，再用Session Manager并以IAM控制管理员会话访问。

**考点：** SSM Agent凭实例角色连接管理服务并承载会话；这条路径不靠开放SSH入站或分发SSH密钥。

私有支撑索引：Q908、Q37、Q319、Q766

## 2. 跨账户代入受限角色 · CA08

**问：** 外部账户的应用要访问本账户资源。需要代入本账户受限身份，与必须保留它原有身份时，授权路径有何不同？

**答：** 代入目标身份时，在本账户建受限角色并信任调用方，调用方获准AssumeRole后取得临时凭证。若服务支持资源策略（例如SQS队列）、且要保留调用方身份，可直接在资源策略授权该外部身份，调用方也须获准该操作。

**考点：** AssumeRole会以目标角色身份调用；资源策略把访问权授给现有调用身份。跨账户不能只看一边的Allow，也不用为此分发目标账户长期用户密钥。

私有支撑索引：Q208、Q634、Q931、Q159、Q222、Q418、Q503、Q521、Q765、Q780、Q870、Q922、Q941

## 3. 几名IAM用户要共享同一套人员权限，新人也能继承。 · CA09

**问：** 几名IAM用户要共享同一套人员权限，新人也能继承。怎样组织？若这组已获批准要访问全部AWS服务和资源，应选哪份托管策略，为什么？

**答：** 把相应身份策略附给IAM组，再加入用户；确需全部服务和资源权限时使用AdministratorAccess。

**考点：** 组使成员继承共同授权；AdministratorAccess以Action:*和Resource:*授予全面访问。它是身份策略，不能把资源策略附到用户组。

私有支撑索引：Q423、Q253、Q387、Q418、Q476、Q751、Q870、Q922

## 4. 多账户员工访问集中管理 · CA10

**问：** 员工要访问多个AWS账户，团队权限不同且经常有新人加入。怎样避免在每个账户重复建用户和授权？

**答：** 用IAM Identity Center管理人员和团队组，为组分配permission set及目标账户，并接入既有身份源。

**考点：** permission set是可复用权限模板；Identity Center在目标账户配置相应角色，团队成员使用已分配的账户访问。

私有支撑索引：Q908、Q28、Q484、Q624、Q688、Q750、Q826、Q922、Q981、Q1018

## 5. 用户池登录，身份池换取AWS凭证 · CA11

**问：** 应用有大量客户要登录；登录后还要让客户端以获准的权限直接访问S3。用户池的登录令牌能直接当AWS访问密钥吗？

**答：** 不能。用户池负责客户登录；需要调用S3等AWS API时，通过Cognito身份池取得受IAM角色权限约束的临时AWS凭证。

**考点：** 登录令牌证明用户已验证；身份池把受认可的登录身份换成AWS临时凭证，IAM角色再决定能对哪些数据执行什么操作。

私有支撑索引：Q1011、Q325、Q345、Q541、Q792、Q803、Q871

## 6. 全球网站从边缘承接请求 · CA13

**问：** 网站要向全球用户交付静态和动态HTTP内容，并减少客户端流量直接冲击源站。应把什么放在源站前，为什么？

**答：** 使用CloudFront分发，以S3或Web应用为源站，并为客户端配置HTTPS。

**考点：** 用户先连接附近的CloudFront边缘；缓存减少重复回源，边缘网络还提供始终开启的网络/传输层DDoS缓解能力。

**易错提醒：** 客户端到边缘和边缘到源站是两条连接，前段HTTPS不会自动加密后段。

私有支撑索引：Q104、Q116、Q155、Q265、Q310、Q313、Q345、Q592、Q871

## 7. Windows文件共享的同步故障接管 · CA15

**问：** Windows应用要保留SMB和AD文件权限，计划维护或一个AZ故障时，还要尽量不丢刚写入的文件。应怎样部署文件后端？

**答：** 使用适配AD的FSx for Windows File Server Multi-AZ部署。

**考点：** Multi-AZ在两个AZ之间同步复制数据并可自动故障切换；它维持当前文件服务，不是等每天一次备份再找回昨日状态。

**易错提醒：** 跨Region每日备份是独立恢复点；它本身不保证发生Region灾难时也只有5分钟数据丢失。

私有支撑索引：Q618、Q97、Q260、Q332

## 8. 静态页面不需要常驻Web服务器 · CA16

**问：** 网站只有HTML、CSS、浏览器JavaScript和图片，没有需要服务器执行的代码。怎样托管可少维护服务器？

**答：** 可用S3静态网站托管或适配的托管静态前端服务。

**考点：** 存储直接返回页面文件，脚本在浏览器运行；PHP等服务器端代码需要计算后端，不能由S3静态托管执行。

私有支撑索引：Q478、Q116、Q205、Q541

## 9. 按请求执行API计算 · CA17

**问：** HTTP请求流量不稳定，可能长期空闲；处理逻辑可放在短时函数中。怎样减少常驻服务维护？

**答：** 用API Gateway接收请求，调用Lambda执行处理逻辑。

**考点：** 入口和计算由托管服务按请求承载，不必自己维持始终运行的Web服务器容量；数据库仍须按数据访问需要选择。

私有支撑索引：Q541

## 10. EKS工作负载各用自己的AWS角色 · CA18

**问：** 同一EKS集群里的不同Pod，需要按各自工作负载身份授予不同的AWS权限。权限怎样绑定？

**答：** 为它们设置不同的Kubernetes service account，通过IRSA关联各自受限的IAM角色。

**考点：** service account的OIDC身份用于取得相应IAM角色的临时凭证，角色权限随这次调用身份生效；应用不必共同使用节点角色作为调用身份。

私有支撑索引：Q223、Q932、Q941、Q1017

## 11. API入口验证用户访问 · CA19

**问：** API Gateway REST API请求进入业务处理前必须验证用户身份。已有Cognito登录，或需要自定义令牌检查，授权检查应接在哪里？

**答：** 接在API Gateway的authorizer：已有适配的Cognito登录时用用户池authorizer，需要自定义检查时用Lambda authorizer。

**考点：** authorizer是入口调用的授权环节，验证通过才把请求交给后端；普通业务Lambda存在不代表入口已经配置授权，API key也不等于用户登录身份。

私有支撑索引：Q587、Q159、Q200、Q541、Q792

## 12. RDS跨AZ自动恢复 · CB01

**问：** 兼容RDS的关系数据库要在一个AZ故障后自动恢复服务，应优先用什么部署？

**答：** 选择RDS Multi-AZ部署。

**考点：** 另一个AZ保留可接管的数据库能力，故障时执行切换；单纯增加应用实例不能恢复数据库。

## 13. EC2与Lambda共享计算承诺 · CB02

**答：** Compute Savings Plan。

**考点：** 它对适用计算用量提供承诺折扣，覆盖EC2与Lambda；只面向EC2实例的计划不能给Lambda用量同样覆盖。

## 14. 跨AZ实例与自动补足 · CB03

**问：** Web计算层不能因一个AZ失效而全部停止，部署时应怎样安排实例？

**答：** 把实例放到多个AZ，并由跨AZ的Auto Scaling组维持所需实例。

**考点：** 跨AZ分散避免实例同处一个故障域；Auto Scaling在实例丢失后补足容量，只有单AZ多实例仍会一起失效。

私有支撑索引：Q450、Q125、Q265

## 15. 入口可公开，后端仍可私有 · CB04

**问：** EC2后端必须保留在私有子网。面向互联网的网站和只供VPN办公室使用的网站，ALB入口应怎样选择？

**答：** 互联网网站用公网子网中的internet-facing ALB；仅办公室使用的站点用internal ALB。后端实例保持私有。

**考点：** ALB接收入口连接后再连接私有目标。入口是否面向公网取决于访问者范围；VPN提供办公室到私网的路径，不必把后端公开。

## 16. 私有IPv4实例通过公有NAT出站 · CB05

**问：** VPC实例要主动访问互联网，又不允许互联网主动连入。出站流量分别为IPv4与IPv6时，各用什么网关？

**答：** IPv4使用公有NAT gateway；IPv6使用egress-only internet gateway，并配置相应的出站路由。

**考点：** NAT为IPv4出站转换地址；egress-only网关不需要替IPv6做地址转换，允许实例发起连接及其返回流量，并阻止互联网发起IPv6连接。公有NAT须放在公有子网，借助弹性公网IP和Internet Gateway出站；私有子网的互联网路由指向它。

私有支撑索引：Q782、Q101、Q125、Q251、Q370、Q470、Q549、Q708

## 17. NAT出口按AZ隔离故障 · CB06

**问：** 多个AZ的私有实例都依赖互联网出站，不能让某一AZ故障切断其他AZ出口，应怎样安排NAT路径？

**答：** 每个AZ部署自己的NAT gateway，私有子网使用本AZ的NAT出口。

**考点：** 如果多个AZ共用一个AZ的NAT，这个AZ就成为共同出口故障点；分开出口才能避免这种连带中断。

私有支撑索引：Q101、Q125

## 18. 在真正HTTP入口应用WAF规则 · CB10

**问：** CloudFront、ALB或API Gateway REST API承载网站请求，要过滤SQL注入、XSS或按登记的客户端IP控制访问，应在哪里做？

**答：** 在实际承载请求的受支持HTTP入口关联WAF web ACL，配置相应内容规则或IP set规则。

**考点：** WAF检查HTTP请求并执行规则；IP set是可复用的来源地址集合，上万地址可分多个集合和规则管理。WAF不直接关联NLB，网络端口规则也不等于HTTP内容过滤。

## 19. 地域访问限制要在入口阻断 · CB12

**问：** 希望按请求来源IP定位到的国家过滤内容访问，应该在哪里控制？

**答：** 在实际入口设置国家允许或拒绝规则，例如CloudFront地域限制或ALB前的WAF地域规则。

**考点：** 依据请求IP的地理定位结果匹配国家规则；服务器部署国家或签名URL本身不会完成这种来源过滤。它不是对人员真实物理位置的绝对证明。

## 20. 外部CA证书要给Regional API Gate · CB13

**问：** 外部CA证书要给Regional API Gateway或CloudFront的HTTPS入口使用，应导入哪个Region的ACM，为什么？

**答：** 将证书导入ACM并绑定实际TLS入口。Regional API Gateway用API同Region的证书；CloudFront查看者证书导入us-east-1。ALB的HTTPS监听器也可使用导入ACM的证书终止客户端TLS。

**考点：** 证书跟随实际完成TLS握手的入口要求；CloudFront的证书Region不由S3源桶所在Region决定。

**易错提醒：** 最低TLS版本另由入口支持的安全策略决定；换证书签发CA，不会改变入口允许的TLS版本。

私有支撑索引：Q62、Q56、Q123、Q532、Q577、Q823、Q855、Q974

## 21. 允许请求后还要看响应方向 · CB15

**问：** 服务器已允许客户端从临时端口发来HTTPS请求。安全组与NACL对响应的放行有何不同，NACL回程应匹配哪个端口？

**答：** 安全组自动允许已放行连接的响应；NACL必须另有出站允许规则，目的端口应匹配客户端的临时端口。

**考点：** 安全组有状态，记住连接；NACL逐方向检查。响应从服务器443端口发出，但要返回客户端当初选择的临时端口，目的端口不是443。

**易错提醒：** 临时端口范围由发起请求的客户端决定；32768–65535不是所有客户端都通用的保证。

私有支撑索引：Q74、Q392、Q884、Q973

## 22. 两VPC直连与中转设备风险 · CB16

**问：** 两个地址不重叠的VPC要让EC2直接私网通信，没有集中检查需求，也不想引入中转设备单点或带宽瓶颈。选什么，路由还须怎样配，为什么？

**答：** 选择VPC peering，并为两边参与通信子网设置指向对端的路由。

**考点：** peering复用VPC基础设施，不依赖单独网关或中转设备，因此连接本身不引入这种设备的单点与带宽瓶颈；请求和响应的路由仍须分别配置。

私有支撑索引：Q262、Q510、Q231、Q237

## 23. 数据库连接峰值用RDS Proxy缓冲 · CB18

**问：** 应用扩缩或Lambda并发会瞬间产生大量数据库连接，怎样减少数据库直接承受的连接压力？

**答：** 在数据库前使用RDS Proxy，并让客户端改连proxy endpoint。

**考点：** 代理池化和复用后端数据库连接，使应用侧的连接波动不必一对一转成数据库新连接；只创建代理而客户端仍直连不会得到这个作用。

私有支撑索引：Q685

## 24. 动态HTTP洪泛按速率阻断 · CB19

**问：** HTTP请求洪泛的来源IP不断变化，固定黑名单难维护。要按请求组的速率限制此类流量，怎样配置？

**答：** 在实际受支持的HTTP入口配置WAF rate-based规则，选择适合该请求组的聚合条件、阈值及Block动作。

**考点：** 规则统计每个聚合组的请求，并对超阈值的组执行设定动作；若按单IP聚合，每个IP都未超限时，不能保证拦住整体分布式流量。

私有支撑索引：Q399、Q437、Q961

## 25. 批量补丁：先看补丁是否受支持 · CC01

**问：** 一批受管EC2要安装补丁：操作系统补丁已被托管工具支持；若换成自定义第三方Linux软件补丁，执行方法应怎样选？

## 26. 已知软件弱点与异常访问行为分开检测 · CC02

**问：** 要找EC2软件的已知漏洞，与要持续发现AWS环境可疑访问行为，应分别选什么？

**答：** 已知软件漏洞用适用的Inspector；可疑行为与威胁迹象用GuardDuty。

**考点：** 漏洞扫描匹配软件版本的已知弱点；GuardDuty寻找异常活动。例如启用RDS Protection后，可分析受支持Aurora/RDS数据库的成功、失败或未完成登录模式，发现异常登录。单纯保存日志不等于完成检测。

**易错提醒：** 威胁发现不等于已经阻断登录；RDS Protection会生成发现，响应控制仍须另行配置。

私有支撑索引：Q315、Q853、Q15、Q329、Q616、Q873、Q924

## 27. 偶发SQL查询直接读取S3数据 · CC03

**问：** 结构化结果或日志已经在S3，偶尔用SQL分析且希望少管服务器，是否需要先搬到自管数据库？

**答：** 用Athena查询S3数据并建立相应表定义，不必先搬进自管数据库；加密数据还要符合其读取格式并配好所需表属性和权限。

**考点：** 查询引擎按表定义读取S3，计算按查询发生。它也支持符合要求的CSE-KMS客户端加密数据，不等于任何自定义密文都能被直接解释。

**易错提醒：** EMRFS上传的CSE-KMS Parquet需禁用multipart；同Region、兼容加密客户端和正确用钥配置仍须满足。

私有支撑索引：Q134、Q199、Q952、Q192、Q341、Q524、Q707、Q975

## 28. KMS密钥：控制权换管理成本 · CC05

**问：** 服务同时支持AWS managed和customer managed KMS key。只要年度轮换和使用审计，与需要自行创建、轮换、禁用密钥，选择有何不同？

**答：** 无自定义控制需求时可用服务支持的AWS managed key；要自行控制密钥生命周期时用customer managed key。

**考点：** AWS代管密钥以固定行为减少管理与固定密钥存储费用；客户管理密钥把策略和生命周期控制权交给客户。

## 29. 自动轮换须匹配密钥材料 · CC06

**问：** 要求KMS密钥按年度自动轮换。能否随便导入一份客户密钥材料，就把它当作AWS生成的对称密钥开启相同轮换？

**答：** 选择AWS生成密钥材料、支持自动轮换的对称KMS key，并开启所需轮换；不能把导入材料默认视为同样支持。

**考点：** 轮换要由密钥管理系统生成并维护可用的新材料；“客户管理”只说明管理权，不说明材料来源与支持的轮换方式。

私有支撑索引：Q189、Q106、Q122、Q202、Q681、Q825

## 30. RDS静态加密保护数据库存储 · CC08

**问：** RDS敏感数据须静态加密。新建库应启用什么；若库已未加密运行，能只加TLS证书改变存储吗？

**答：** 新建库启用KMS静态加密。既有未加密库可制作快照、复制并加密该快照，再恢复为新加密DB并计划切换；加TLS证书不会加密存储。

**考点：** 快照复制实际产生加密数据，恢复的新库继承加密；客户端传输TLS和密码保存各保护不同边界，均不能替代静态加密。加密DB的后续自动备份和快照也保持加密。

私有支撑索引：Q838、Q121、Q330、Q349、Q438、Q529、Q901

**问：** Lambda或Managed Grafana有访问权限，要读取私有RDS。仅有IAM权限或创建RDS interface endpoint就够吗，应连接哪里？

**答：** 不够。为函数或工作区配置VPC连接，选有目标私网路径的子网并放行实际安全组，连接数据库自己的私有endpoint和端口。

**考点：** IAM决定允许做什么，VPC连接提供网络路径；RDS interface endpoint用于创建、修改等管理API，不承载MySQL等数据库SQL连接。Lambda也可沿已有私网路线到本地数据库。

**易错提醒：** Grafana不需为此把RDS公开；网络连通后仍须满足数据库实际登录授权。
