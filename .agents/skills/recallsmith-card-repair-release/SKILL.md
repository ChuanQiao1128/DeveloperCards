# RecallSmith 修卡与发布

## 固定教学写法

每次开始写卡、修卡、审卡或在聊天中建议卡片，先实际读取当前项目AGENTS.md第4.0节“手机记忆卡设计规则”（版本 `mobile-memory-card-v2-20261118`）；该节为当前统一入口。以下摘要仅作操作索引，不能替代完整规则。只读取该小节，不反复加载项目历史。无仓库上下文的作者／Reviewer须在实际指令中收到完整正文、版本及SHA-256；派发前核对输入，不能假定现有脚本会自动加载AGENTS。

用户逐张参与的聊天校稿可直接讨论或保存确认文案，不启动整批作者调用；草稿不升级为发布验收。不得为关联题数扩张回忆任务，不能用Legend或“综合练习”解释超量内容。先保证手机可读、一个有用判断及关键原因，再按当前卡面核对真实题目支撑。

1. 一张卡回忆一个有用判断及关键原因。正面给场景、决定条件和明确问题。
2. 背面默认答＋考点：答给行动，考点解释条件为什么导向行动；仅必要时留一个提醒。
3. 必要术语解释作用；不堆配置、弱干扰项、审计说明，不机械限字。
4. 保留必要条件，英中等义；承担当次必答的新知识须已教在可见正文或明确先修。
5. 答案只答所问；题面已给条件不再列为必答。不得直接将含补充说明的整段答案复制成评分要求。
6. 精简不强行改变学习目标。事实错误、缺证、删去必要判断或范围变化必须显式登记，旧题卡覆盖不能自动沿用。
7. 格式／引用存在不是事实或教学PASS；设计支撑不等于学习者记忆或正确率实测。
8. 保留UID、顺序和学习记录；revision按既有机制更新，可能使卡片重新到期。

表达基准：问“多个账户、不同团队、新人频繁加入，怎样统一授权？”；答“用Identity Center按团队组分配权限模板及目标账户”；考点“模板决定能做什么，账户分配决定在哪里做；新人入组沿用授权”。范例不作为其他技术事实的证据。

## 执行：主聊天只调度

- 当前批次默认5张。区分仅改稿、测试与已授权发布；节奏不构成新增授权，不恢复暂停的全库任务。
- 优先使用`tools/aws_cards/repair_batch.py prepare/run`：作者与独立Reviewer分别向既有本机Responses代理进行一次冻结文本调用，沿用同一认证及模型，不启动完整编码Agent携带插件、Skill目录或聊天历史。主聊天只调度和验收，不传旧PASS或作者自评结论。代理失败保留记录并停止，不自动重试或换通道。
- 每批一次改写、一次独立审查，最多一次有必要的定向返修。现有合格稿及未变依赖先做精确内容／版本／规则绑定再复用，不重做第1—10张。

### 唯一模型数据格式

每卡只保留一份语义字段：`uid,frontEn,frontZh,answerEn,answerZh,keyPointEn,keyPointZh,watchOutEn,watchOutZh,goalEn,goalZh,mustAnswer,evidenceIds,scopeChange`。无提醒时watchOut双语均为空串。旧卡与候选都用该格式，省去重复的`teaching`、`explanation`、Markdown、tag、哈希和来源全文。身份、顺序、原始数据、证据版本及文件哈希在旁路清单保存。

包内有本批旧稿、相关完整官方摘录、必要依赖、本教学摘要和一个范例；需要核题时保留相关原题全部条件及选项。目标20—25KB，超出时先去重或拆批，不截断必要条件。已绑定官方资料可复用；只为缺证或新主张补源，不重新遍历题库或全部语料。

作者只输出该格式的候选及真实scopeChange，不写报告或自行宣告PASS。Reviewer必须看见候选实际正文、必答点和相关证据；每卡检查FACT/B1/U1/R1/T1/S1/P1，通过项合并简述，失败项说明具体字段、原因及必要修改；批内保留两项代表性条件迁移。未测原题支撑时明确标待重核。

### 同轮受限修正

Reviewer可在同轮给出精确的删除补丁，仅删除重复话语或题面已给的评分要求，并核对该确切补丁。脚本应用、同步双语／兼容字段、保存新旧哈希及原FAIL；应称“审查后受限修正与校验”，不能冒称新一轮独立复审。新增技术主张、补决定条件、改变结论或范围必须交回作者，再用唯一一次局部复审机会。不能自动把FAIL改为PASS。

## 机械工作与计量

使用`tools/aws_cards/repair_batch.py prepare/run`完成原句及哈希预检、两次独立文本调用、渲染、Linter、真实解析与计量；一次必要局部返修保留原FAIL，由`finish-repair`核验新旧正文与审查绑定后收尾。细节见`tools/aws_cards/repair_batch.md`。`repair_cards.py`仍只负责本地序列化。官方证据不截断，审查输入可移除候选未使用的证据；云端文件读取限15秒，优先传本地快照。输出schema在本地验证；凭证只留内存，禁止代理重定向。这些工具不能代替语义审查、服务器绑定或发布门禁。

时钟区分一次性工具／规则修复与后续真实批次，均保留实际起止；不能隐藏前者。用已有本机token_count事件在同一收尾步骤计算本批主任务和子任务用量，只读取本次会话的计量事件。缓存输入、非缓存输入、输出分别列出；推理已含输出时不重复相加，尾部未观测标unknown，不推算费用。

用户最新接受每5张约10分钟，替代此前5分钟目标。常规预算从取卡／资料准备开始，含改写、独立审查、最多一次必要局部返修、导入校验与出稿；已授权发布及核验计入实际总时长。2万token仅作观察参考，既有明确预算门禁不变。优先稳定交付，只改确认有问题的部分；符合当前写法且证据绑定有效的合格内容保留。不为追速度数字重做合格稿或另起工具重构。预计超时及时说明具体卡和阻点；缺证不报PASS，一次返修仍未闭合则保留待处理状态，不静默反复调用。真实工具故障才做必要修复，并记录维护及总耗时。

2026-11-18局部实测：直接沿用本机代理的两卡独立复核为34秒、输入2730／输出1192 token。此前完整编码Agent的单卡局部改写输入21656 token。任务及输入不同，只说明附带上下文有节省空间，不据此宣称五张整批耗时、用量或学习效果已达标。

## 仅在授权范围发布

发布时才读`frontend/docs/aws-basics-release-bundle.md`的自动发布／恢复契约。绑定真实独立审查和服务器版本，不伪造PASS或人工审查声明；使用Console `/decks/release?deckId=15` 的 **Run reviewed release**。纯内容不另发OTA、不额外启动App全套CI，必要内容检查及仓库强制门禁保留。

恢复先查询，继续同一releaseId／actionId／正文／job／build；遵守lease、退避和上限，不换key绕错误。job、live指针、索引、公开manifest、实际下载SHA和全部双语身份／顺序／revision／正文一致才报告完成。只给改稿、验证状态、耗时／用量和产物路径；不让一批内容修订扩展成无关基础设施改造。
