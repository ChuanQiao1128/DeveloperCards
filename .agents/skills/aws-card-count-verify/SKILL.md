# AWS卡数闭环验证

目标是确定**足以支撑约定题库、符合短卡标准、没有已确认重复教学的实际卡目数量**。不能把目标数、主题数、映射条数或已生成文件数当作已经验证够用的卡数。无需声称求出了数学最小集。

在RecallSmith项目使用时，先读[项目入口与恢复](references/recallsmith-project.md)，接续当前运行；其他AWS题库从其现有状态开始。项目AGENTS.md和用户最新教学标准是卡片粒度的依据，不重新发明教学方法。

## 开始与恢复

- 确定题库范围、用户明确排除项、当前卡体、领域分类和有效证据。沿用原始计时、预算、尝试次数及失败历史。
- 复用已有考点、题目、官方摘录、当前正文和有效审查；禁止重新提取全库考点。旧证明只在正文、题干全部选项、必要条件、先修和规则的实际依赖仍匹配时复用。
- 为每个卡目区分：仅有目标、已有正文、当前事实/教学通过、已有逐题支撑。计划表写着“complete”不证明后面三种状态。
- 默认一名作者。确定性检索、排序、哈希、去重和统计用现有本地脚本；必要独立复审只派最小冻结输入，`fork_turns: none`，写入目录分开。不继承作者分析或预期答案。

## 持续执行的闭环

1. **落实实际短卡。** 一个主要判断及关键原因；已有正文不重写，仅补缺和受影响修订。数量验证可先用中文短稿，暂不做双语封装。正文的答、因果、边界须有AWS官方原句、URL及可回查快照；未证实的草稿不算通过。
2. **用卡面回测原题。** 对每道原题读取完整题干、全部选项及决定性条件，只把实际可见的相关卡组和必要先修作为所学知识。每个必要推理前提引用具体卡句，解释正确方案为什么成立及真正竞争方案差在哪里。不得用私有目标、题解、答案字母或审查者记忆补缺；不要求为排除弱干扰项背完整服务手册。
3. **定位失败并定向修正。** 区分事实错误、卡面未教、先修缺失、条件省略、记忆任务过载和题源问题。先修正确事实或解释、复用现有规则，再考虑新增。只重审变更卡、真实依赖和受影响原题，不批量推翻有效结果。
4. **做删除与合并核查。** 优先检查只关联1—2题的卡。移除它后，其他可见卡能可靠推导必要判断，则删除重复教学并回测；相同条件、动作、机制可合并。独立能力不能硬合，不能把若干小任务藏在一个长背面或私有附录来减数。批量删除时，替代卡和必要先修必须仍在拟保留集合；分别可删不代表能同时删除，须用整个拟保留卡组检查，防止两张候选互相替代后一起消失。暂不能证明可删的项目照实保留，不将贪心删除称为数学最优。
5. **更新证据与计数，继续处理未通过项。** 每批5—10张卡或适合输入规模的题目落盘。保存`current_artifacts`、`pending_ids`、`findings`、`attempts`、`next_action`及实际证据绑定。使用已有运行状态即可，不另造编排服务。每轮完成后继续下一未完成批次，不以又写了计划或又得到候选数结束验证任务。

## 题源疑点不能被用来掩盖卡片缺口

- 先区分“当前卡没教会”和“原题确实有问题”。只因没有部署参数、没排除所有假设、缺证据，不能确认原题错误。
- 确认无有效选项，须给出原题硬条件及所有候选不满足的具体原因；确认多解，须证明至少两个方案在题干通常语义及实际优化目标下都成立。优先评估题目所问的最佳方案，不把普通省略都升级成不可答。
- 保留`SUPPORTED`、`CONDITIONAL`、`INSUFFICIENT_CARDS`、`SOURCE_ISSUE`、`UNKNOWN`等真实状态。条件和未知不能折算充分支撑。疑点采用原文锚点及必要官方证据，不把“尚未找到支持”写成已证伪。
- 验证的是原题选型所需知识，不是部署每个场景并实测生产SLA。若可见卡组已足以在全部选项中作出有依据的唯一选择，把容量实测、恢复演练等实施验证单列；不能仅因这些尚未执行就推导出需要另一张卡。原题给出的硬容量、协议、时限与成本约束仍须实际参与判断，不能用一般最佳实践覆盖冲突。
- 不改写原题后冒称原题已覆盖。修正建议、证据和用户明确接受的范围例外另记，原题分母保留。未经用户接受的未解决题源例外不能使“完整题库覆盖”门禁通过。

## 何时才可宣布最终卡数

以下条件须同时成立，并由当前版本证据支持：

- 所有选中卡均有实际正文，事实、理解、回忆任务、自评和必要先修检查通过；普通卡仍是一个主要判断及原因。
- 约定范围中所有题目均有当前可见卡组的充分推理证明；范围例外须是用户明确接受的例外，并在报告列出，不能默默删题。现有需求判断均有明确去向，但不机械一判断一张卡。
- 低频卡和已发现归并机会已处理，删除或合并未造成未登记缺口；没有未关闭的阻断性事实、教学或题卡支撑问题。
- 当前卡体、完整原题、必要先修及审查规则指纹匹配；独立复审和确定性完整性回读都覆盖当前版本。旧PASS与来源链接存在本身不能放行。
- 全库以实际唯一卡ID计数。主归按卡片核心判断对齐考试领域／任务，核对已有分类与归属理由；不能为均衡数量或沿用题目主归而随意分配。每卡恰好一个知识主归领域，四域主归数之和等于全库N。各领域共享引用按相关题目及递归先修的实际卡ID去重，允许重叠，不能相加。

满足后生成Markdown报告，首屏给出N及四域“唯一主归／含共享实际复习数”，附卡目、逐题证据和删除/合并记录。明确设计支撑与学习者真实记忆、做题正确率的区别；后者未实测就不宣称已经提高。

## 持续推进与真实边界

- 用户说“验证”“继续”“一直验证到确定数量”为止，即执行闭环并持续推进，不反复请求已授权步骤的许可。发现未通过项继续修，不换个名字提前宣布完成。
- 相同策略连续三轮没有新证据或修正进展时，换来源、检查原文或缩小具体问题；不原样无限派审。同一修订的失败及修复次数保留。
- 确实需要用户决定题源修正/范围、授权不足或触及既有预算上限时，保存精确阻碍并提出必要的具体问题；独立工作继续。不编造答案、扩大预算、沉默删题或填一个“最终N”来结束循环。
- 未满足门禁只能报告已验证多少、哪些未通过及下一动作，不能把核算任务标记完成。只有当前核验执行会推进；中断后由状态恢复，不擅自启动后台服务、自动化或外部模型通道。
- 本Skill不授权发布、OTA、修改学习进度或生产库存，也不以“验证”为由重置历史计费。
