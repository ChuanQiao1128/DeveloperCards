# G-need：全库必要知识与判断条件索引

版本：1.1，2026-11-02。作为主计划v5.3的第一内容阶段，复用当前RUN与原始账本；不是新工作流、事实报告库或发布任务。本轮只修改计划，所有实际抽取/归一化/检索/模型批次保持暂停。

## 1. 当前事实和完成含义

原始账本1019条：verified59、pending959、held1；held是已被用户排除的已排除的缺选项题，没有10条review_required。要求集合为原始题号集合去掉用户明确排除的一题，共1018，**不连续**。现有题干/全部选项已结构化，prepare.load_source可只读复用；不得执行旧prepare.init重建或重置账本。

59份旧分析含原文锚点、判断和局部目标，是可复用资产，不仅有analysisOutcome摘要。其旧核验状态不等于新需求索引、全局映射或新卡通过。G-need只形成候选需求/目标；不宣布原题正确选项，不计入新增verified题目覆盖，不冻结最终N。

依赖：只读输入盘点→规范视图→全库需求索引→候选目标聚合→按主题证据定位与直接制卡。全量需求先看齐，再全局组织目标；不按题号每批抽完即持续写全量卡。后续50题闭环复用本索引，不再重复一轮需求抽取；50题仍用于测双语制卡、教学/事实/逐题审核与真实单价，不决定全量卡数。

## 3. 归一化仅处理表示，不猜补题意

复用已提取的question_stem/question_option，排除印刷答案、讨论、旧卡结论及无关页内容。记录qid/questionRef、sourceSha256、stem、全部options、sourceFlags、normalizedTextSha256，并引用原始blockId、位置及已有修正依据。模型包只带源视图和必要flags，不反复带长元数据。

选项用稳定ordinal区分，保留原始标签，即使标签重复也不改写成猜测的正确序列。长题的多个源块不得因拼接丢失否定、数字、单位、表格或条件。归一化哈希不同于原PDF/source哈希；字符偏移必须指明对应视图。

优先复用已按位置核对的旁注；字体/编码/字宽等唯一证明成立时才自动恢复连字。未证明的NUL不按词典猜改。模型默认读规范视图，但必须能回溯原文；影响关键条件/选项可读性的异常挂blocked_source，非阻断旁注保留。异常记录不等于用户同意排除题目，不计已核验覆盖，也不要求先恢复全书才处理其他题。

纯脚本执行不调用模型；编写适配、模型诊断或必要视觉仍有消耗，按实际计量。不宣称整个准备/账户消耗为零。

## 4. 窄需求记录与批量决策

模型只输出qid、conditions、mustJudge、toVerify、anomalies及已提供的sourceIds；版本、偏移、哈希、谱系和落盘由脚本处理，不让模型计算字符偏移或抄长原文。

- conditions：决定判断的条件及源锚点；有明确条件的正常题非空。
- mustJudge：需要学习者回答的技术问题/能力，而非服务名单；关联条件。显式要求与隐含先修候选须区分。
- toVerify：未明确的技术区别、术语、冲突或先修问题；开放提问，不凭模型记忆判正确选项/干扰项输赢。可为空，空不表示技术事实已通过。
- anomalies：源/语义异常，可为空；不为满足schema虚构异常或疑问。

anchors优先复用blockId/选项ordinal；需要更细定位时由脚本绑定明确原句跨度，不唯一时保留整块及定位待处理标记，不因一处字符差异废掉整批。extractionStatus区分extracted、needs_repair、blocked_source；extracted仅表示草案抽取完成。事实/证据状态单独在verify-ledger记，不使用含糊done当verified。

默认每包最多100题，同时受源正文及必要包装约120KB和实际上下文/输出能力限制；长题缩批。首批50题校准短schema和遗漏类型，通过方法检查后再扩到100；这是G-need首批，不是重新创建50题制卡试验工程。完整性优先，150输出token/题仅是测算假设，不是迫使漏条件的硬截断。

旧59条默认先从完整requirements、judgments和proposedObjectives做可追溯、无损投影，校验原始来源和现有审查绑定，不只对analysisOutcome摘要。字段或含义不能等价迁移的题再定向补抽；投影语义校准如发现系统性差异，记录原因与成本后扩大重抽范围，不默认全部重做。投影不能把已验证事实改写成新开放问题时丢限定，也不能把旧结论的存在当新schema合格。

需要校准旧题口径时，独立输入先只给原题，不给旧结论/映射；输出冻结后对照旧完整要求与判断。额外读取、对照和重抽单独记成本，不把旧样本叫未见盲测，不因新阶段重置旧发现的修复次数。

## 5. 聚合：服务分桶只是候选路由

先用题干判断能力、关键条件和已提取need的词面做粗筛，选项服务集合只作辅助线索，避免被干扰项服务带偏。模型审候选目标的含义和适用条件是否一致，不给所有题做全量两两比较。

聚合单位是必要判断/学习目标，不是一整道题。单题可挂多个目标；跨服务条件不能因分桶而拆丢。相同目标在不同服务词或不同簇中仍可能出现，保留跨桶候选近邻和冲突/未归并项的轻量检查，不能只审同桶而遗漏同义目标。

候选目标最少保留objectiveId、goal、conditions、needRefs与qids、compositionRefs及当前候选状态；不再生成oldUidCandidates或旧卡语义身份匹配。source conditions随需求保留；service相同、向量相似、相同模板均不是合并依据。

用户已完全放弃旧347卡：不再读取旧正文、旧目标/标签目录来聚合或匹配UID，不再做347逐卡主去向或旧进度迁移。**全N张均从原题需求及官方支持形成新目标、分配全新UID、生成新双语正文并当前审核**。N不以347为目标或扣减基数。原题独立分析59条及官方原文缓存保留，仅复用可追溯条件/判断/证据，不投影旧卡关系或旧UID。历史旧卡留档，不成为新包RAG知识源。

cardCountRange可暂为空并说明待核验/待拆分；若给范围须绑定目标分配依据，不能每个目标盲设1卡后求和。先得候选目标数及有依据的卡数范围，正式制卡/教学审核可拆合补充，覆盖闭合后才冻结最终N。不能继续用450作为当前规模预测。

direct_test/prerequisite/partial此时最多是candidateRelation，不作为已验映射。最终关系取决于当前实际卡片教了什么及整题卡集能否闭合，必须在原合并终审确认，不能在G-need提前冻结。

## 6. RAG：按共享疑问定位证据，制卡时消化

第一遍不为每题默认检索整套AWS长文；术语确实阻碍提取时才按需查，否则挂疑问继续。聚合后按共享疑问与适用限定检索实际AWS官方上下文，优先复用本地BM25及已有语料，不新建向量数据库、持久化索引或GraphRAG。

topicId只是标识，共享键须包含能力、操作/部署/区域等限定；不能因为同叫aurora就复用结论。verify-ledger最少保留topicId、question、scope、status、needRefs与证据ID。实际URL、sourceVersion、quoteSpan保存在既有证据对象中，通过引用复用；不让模型为所有主题再写一套fact正文并单独审核。

证据已找到只能记evidence_located，不自动记事实verified或题目covered。证据可补充隐含先修、纠正错误聚合并生成新需求版本；变更保留谱系和受影响关系，不覆盖原始草案。实际正选机制/竞争项排除理由在基于官方上下文写卡及同轮终审核验，证据不够保留UNKNOWN。

“之后不再读原题”不能作为成本保证：制卡作者尽量复用短需求，但最终独立逐题覆盖审核必须读完整原题和所有选项，必要问题也须回源；这些调用按真实输入再计。

## 7. 门禁边界与未解项

程序检查要求集合精确相等、当前qid唯一、源/规则版本、全部选项保留、锚点可解析、数组类型、旧59处理去向与每条mustJudge的目标关联。toVerify/anomalies允许为空；不能用“四字段非空”鼓励填充废话。每题至少一个目标只是最低结构条件，不等于每项判断已覆盖。

coverage-check分别输出：sourceAccounted、needsAccounted、extractReady、aggregationStructurallyReady、blockedSourceQids、repairQids、orphanNeedRefs、unresolvedTopics与semanticReviewPending。全1018有记录不等于全1018可用；有必要blocked/needs_repair或orphan就不能宣称G-need完整完成、蓝图已验或最终N已冻结。

未解项可不阻塞其他可读题/目标的草案工作，但保持必需范围并继续可见，不能静默从分母移走；最终全包门禁不接受必要缺口。源歧义可单列，不能靠改名为source_ambiguous自动豁免覆盖。

语义完整、同义目标是否真能合并、条件是否遗漏，不能由集合/哈希脚本证明。首批/风险例用于方法校准，最终所有必需题仍由独立Reviewer从原题查条件并核当前卡片；不提前重复一轮全量事实/覆盖终审。

正常路径是两类G-need语义任务：需求抽取与候选合并判断，均分批执行，不是全项目仅两次模型调用。失败、必要回源与修复会有额外调用，全部记账；原作者/独立Reviewer/模型通道不变，无大规模并发或新框架。

## 8. 成本算式：只计真实读取，不双算

Kimi给定假设：每题读500token、写150token。若全1018都模型抽取，1018×(500+150)=661700，其中阅读509000、输出152700；再加假设的聚合50000–100000，小计711700–761700。前述40–60万若就是同一遍源阅读，不能再加一次。

若仅959条需模型抽取，示例为959×650=623350，加聚合50000–100000为673350–723350，另加旧59兼容/校准/必要补抽等真实调用。全59重抽至少按该假设增加38350，而非几千token；这些均是算术情景，不是实测预算或完成承诺。

真实G-need成本还含每批规则/schema/工具头上下文、实际输入/输出与推理口径、候选合并输入、修复、失败、必要查证和准备诊断；推理若已含output不重复相加。归一化存文件不等于后续模型读文件免费，缓存也不等于输入token消失。原生监督/视觉U未知，不记零。

先测第一批实际usage和墙钟，再据剩余未处理题及候选规模预测余量，不用固定500/150反推已知总额，不根据N450猜全量工期。G-need的总预算/单请求强制上限目前均未获得保证；原50题制卡试验10万/30分钟阈值不是本阶段1018题的隐含支出授权。本轮不执行；未来仅在认可的阶段范围及预算内继续，无需每批重复确认，达到限额不派下一调用并保存全部结果。
