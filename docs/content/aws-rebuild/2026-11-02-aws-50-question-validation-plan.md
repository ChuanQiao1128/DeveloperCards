## 3. 执行步骤与尝试窗口（约 45–60 分钟）

| 步骤 | 具体做法 | 规划窗口 |
| --- | --- | --- |
| **0. 轻量准备** | 冻结 50 题清单；直接复用现有 `blockId`、选项编号和源哈希（不预建持久化索引或复杂分句系统）；仅按确定依据恢复本批 `<NUL>` 连字；将本批检索查询一次交给现有 BM25（单次构建索引） | 目标 15–20 分钟 |
| **1. 复用需求与确定疑问** | 读取G-need当前版本的50题需求、目标和源旁注；仅对版本变化/缺口定向回源，不重做一遍全样本抽取；竞争差异仍为待查证问题 | 计入最多30分钟内容试验窗口 |
| **2. 共享官方证据直接制卡** | 按服务/主题分桶组织本批需求（桶内保留部署、区域、协议、成本、运维等条件差异，不按服务名粗暴合并），取实际 AWS 官方文档块直接生成双语卡，并运行 `lint-deck.mts` 检查格式 | 同上 |
| **3. 合并终审与失败微批修复** | 零作者历史的独立 Reviewer 同时读取原题、官方依据与双语卡，分别给出**每张卡事实/双语/教学结论**和**每道题判题支撑结论**；缺陷给出稳定ID与修正动作，通过项即刻保存，仅对失败项及变化依赖微批返修（每项最多2次，不因拆补卡重置） | 同上 |
| **4. 汇总与全量重估** | 对照 10 道回归题，汇总三类判题支撑统计、合格双语卡包、失败原因、真实 token/耗时，并更新已知目标/候选N范围及单位成本；最终N未定时不宣称已算出全量工期 | 5–10 分钟 |

**窗口说明**：约 **45–60 分钟**是一次受控尝试的时间安排，不是保证 50 题全部闭合的承诺工期；若准备阶段 20 分钟内遇到确需补充的小脚本或源区域核对，据实记录耗时，不无限扩大工程范围。

## 4. 判题导向制卡与合并终审口径

1. **正面明确目标，避免提示答案**：选型题给出业务约束/故障/冲突，不先指定正确方案；机制题可以写出所研究的服务。Easy允许必要用途和术语解释，Rare练决定性条件与竞争方案，Legend练有明确必答点的组合。每卡一个主要目标，不为凑张数捆绑独立目标。
2. **背面固定三段判题结构**：
   - `答：` / `Answer:`：直接回答；Easy/Rare简短，Legend可列必须命中的要点，保持首行明确结论；
   - `考点：` / `Key point:`：写一条官方依据支持的核心机制或条件规则，不重复首句；必要术语用短语解释；
   - `易错提醒：` / `Watch out:`：写清高频竞争干扰项输在哪个具体条件上（无真实混淆点可省）；
   - `SOURCE:`：绑定官方 URL 与精确原句；公开卡面绝不出现原题文字、答案字母、讨论、私有题号映射或本地路径。
3. **仅凭卡片盲答判题核验（核心门禁）**：
   - Reviewer不看印刷答案，要求每个决定性推理定位到当前卡片具体内容；查官方原文核事实，但不能用原文或模型记忆弥补卡片未教授的知识后记覆盖通过；不把这一检查宣称为已证明能禁止模型使用自身知识；
   - **即使选对方向，只要推理依赖卡片未教授的必要条件或机制，一律判该题覆盖不足（`FAIL`）**；
   - 单张卡相对综合题仍如实标 `direct_test / partial / prerequisite`，但整道题关联的卡片集合必须联合闭合（原题自身歧义或漏参单列 `source_ambiguous`）。


4. **教学缺陷直接变成返修动作**：执行 [AWS卡片教学审查规则](aws-card-teaching-review.md)，作者先明确主目标、mustAnswer及Legend先修；Reviewer同次检查U1理解、R1回忆、T1迁移、S1自评。事实、双语、教学与逐题支撑的必选结果分别保留。只修实质缺陷，NOTE不阻断；允许合格卡不改。失败项带位置、规则、稳定findingId、action与affectedIds，不重复抄卡或来源；按需要改正面/背面、拆卡、补先修/必要变式或修映射。目标、限定或先修变化时重查相关卡和原题，拆补卡沿用问题/修复谱系并更新实际N与预算。
5. **结果只说明本轮检查范围**：新增维度证明的是教学设计符合规则，不证明学习者已经长期记住或提高做题率。长期效果需延迟无提示作答和换题数据，本次不自动增加用户研究。将本规则实际内容与哈希纳入作者/Reviewer冻结输入并完成必要相关控制后，才记为“执行了教学审查”；本轮仅落地文档，未接入执行脚本。

## 5. 成本口径、停止阈值与成果复用

- **统一 10 万可观测 token 阈值**：不再默认额外追加 3 万 token 准备预算。纯本地脚本运行为 0 模型 token；准备期若发生最小适配诊断或必要视觉核对等可记录模型调用，与步骤 1–3 的作者、Reviewer、上下文及返修调用**统一计入 100,000 可观测 token 累计派发上限**。主对话与原生不可观测用量仍单列 `unknown`，不冒充全账户硬扣费上限。
