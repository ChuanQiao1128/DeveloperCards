# AWS 卡片教学审查与定向修正规则

版本：1.1，2026-11-02。由作者和独立Reviewer共用，嵌入既有合并终审，不增加模型角色、独立事实报告或新的常规审查轮次。

## 作者在写卡前明确什么

每张卡只声明一个主要学习目标，按已有私有元数据关联必要题目条件及官方依据。Easy学习用途/机制；Rare学习一个核心区别或条件变化；Legend学习一个有明确判定标准的组合问题，允许多个必要步骤。不要把多个互不依赖的学习目标塞入一张卡。

私有草稿为每卡给出简短learningGoal、mustAnswer要点，Legend另列prerequisiteCardIds；复用现有等价字段，避免另建数据模型。mustAnswer只列决定正确性的必要点，不要求逐字复述。以上元数据不增加手机背面栏目，不把原题/答案/私有映射导出。

正面应让学习者回忆或推断，而非复制题干中已给出的答案。机制题可以写出被研究的服务；选型题不能先指定正确方案再问为何正确。必要概念、用途和术语解释可以进入Easy，不一律禁定义，也不把所有Easy拉长成综合题。

背面保持答／考点／易错提醒三段（Answer／Key point／Watch out）。答直接回答；考点提炼一条关键机制或条件规则；提醒只写真正会改变选择的区别，无实际风险可省。三个栏目不机械重复同一句话，不为固定字数删除必要条件。Legend可在“答”内分点，使mustAnswer能被自评，不加第四个公开栏目。

## Reviewer同一轮检查

仍先核查当前AWS官方支持、限定、双语等义与真实题目覆盖；再用以下教学规则检查每张卡。教学判断是设计层面的合格性，不能宣称已证明学习者长期记忆或提分。

| 规则 | 问什么 | 何时需要返修 |
| --- | --- | --- |
| U1 可理解 | 核心术语是否足够解释？原因能否说明结论？必要场景条件是否完整？ | 缺失解释或条件足以让目标学习者误解；修正背面/限定或补必要先修 |
| R1 可回忆 | 正面是否有明确、可作答的任务？是否泄露待选答案？主目标是否单一？ | 不看背面也能机械抄出答案，问题无明确回答范围，或捆绑多个独立目标；收窄/改写/拆卡 |
| T1 可迁移 | Rare是否教会真正决定取舍的条件？Legend是否有多个约束与完整先修，是否暗含新事实？ | 只靠服务关键词匹配、缺必要区别、无法说明关键竞争方案为什么不适用，或组合题夹带未教事实；补条件区别/先修/必要变式 |
| S1 可自评 | 答案是否直接回应？哪些点答到才算完整？等义回答是否也算正确？ | Legend只罗列服务名、遗漏必须措施仍看似答对；按mustAnswer重写答案，或收窄问题 |

事实/双语与上述必要维度分别给结果，任一必选维度有实质FAIL/UNKNOWN，该卡不算接受。不要因无学习者实验就把“记忆效果未知”当设计FAIL；不要把措辞偏好、句长审美或可选例子当必返修项。

全部卡都过上述检查；不要求每张都有修改建议。Easy不必强加选项竞争，Rare不必一律多选，Legend可以多步骤而非强拆成多个碎片。对本批少量代表Rare/Legend可在同次审查内改变一个关键条件，判断规则是否仍被误套；只展开发现的问题，不为全卡再生成一套变体题。该代表性检查不替代全部卡和全部必需题目的检查。

## 判题支撑如何核查

Reviewer可查官方原文核事实；核查原题是否被卡片支持时，每个决定性推理必须定位到当前卡片具体段落/要点。不能用官方原文或模型记忆填补卡片未教授的知识后记PASS。不看印刷答案；题号命中、主题命中或猜对答案都不能抵扣必要条件缺失。

逐卡结果与逐题结果独立保留：资料可能技术正确但难以学习，也可能单卡清楚却不足以解完整综合题。源残缺/歧义按原计划保留真实状态，不靠教学改写补造原题。

## 小报告与可执行返修

通过项：仅ID、当前版本、必选检查结果与依据关联。不复制整卡、官方原文或全部推理。

发现项最少记录：findingId、cardId/questionId、ruleId、status（REVISE/UNKNOWN/NOTE）、具体缺陷及位置、action、简短修正要求、affectedIds。由脚本补版本/哈希，不让模型机械抄写。严重性以是否影响当前目标与覆盖决定，NOTE不阻断；REVISE和必要UNKNOWN不算PASS。SOURCE缺失须补实际证据，不能靠润色解决。

action只需使用现有返修记录中的等价动作：rewrite_front、rewrite_back、split_card、add_prerequisite、add_condition_variant、repair_question_mapping；事实或来源缺口沿用原有实际补证据动作，不能以文案润色替代。允许多动作共同修同一发现，但不把同一问题换名计成新问题。

示例：
- 第8张演示卡同时承载自动读伸缩、Reader前提、连接路由与读取新鲜度。若被判为多个独立目标，优先保留自动伸缩及其必要前提；将独立的读取路由/新鲜度目标拆成另一Rare卡，并修正Legend先修与原题关系。拆分不是按句子机械切割，也不为凑N省略知识。
- 第7张若只会背380秒而没有解释配置目的，应补明“为批次处理与节流重试留余量”，保留Lambda/SQS适用范围和建议值口径；不扩成另一份事实报告。
- Legend答案以必要约束为自评点，不能仅有“用SNS/SQS”或“用Aurora”；但不要求背固定词序或额外服务。

作者只修REVISE项；Reviewer重审改变的卡及受影响关系，合格项不随整批重跑。每项最多2次自动修复，旧问题计数、既有特许返修题已用第3次例外和已排除的缺选项题排除均保持；拆卡/补卡/换UID须沿用原finding与修复谱系，不重置次数。新包使用全新UID，不再做旧347目标对齐或进度迁移；新包内部目标拆合仍保留身份/修复谱系，不能借换UID重置失败次数。旧卡归档，原题与官方证据及59题分析继续按当前规则使用。

若改变事实、限定、主目标、难度/先修、mustAnswer或卡片映射，重查相应官方支持、双语等义、依赖卡及关联原题；仅纯标点/排版改动可走对应确定性检查，不重开无关题目。补/拆卡计入实际N及本轮预算，不隐形增加预算。

## 计费、证据和实际接入状态

本规则不增加常规模型轮次；作者预先遵守，独立Reviewer同一packet合并检查，脚本仍做确定性校验。新增读写字段和判断的真实token/耗时可能增加，计入既有100000可观测token/30分钟内容派发阈值；不能称零成本或预先缩短工期。长期记忆/实际提分须延迟无提示作答与换题数据验证，本轮不自动发起用户研究或消息。

本次落地范围是计划与可复用作者/Reviewer指令，尚未接入或测试执行脚本。未来启动试点时，应把本文件实际内容和哈希放入作者及Reviewer冻结输入，复用现有正反例控制校验一次；只检查相关接入，不建新平台或新审计项目。只有实际消费本规则并留下当前检查结果，才能说该批执行了教学审查；文档PASS不能作为任何新卡内容PASS。
