# AWS 全量考点蓝图与卡包重制计划

日期：2026-11-02（Pacific/Auckland） · 版本：v5.3（全新卡包，移除旧卡复用与迁移）
状态：计划已更新，执行继续暂停；未经用户明确启动，不恢复 `aws` 自动化或派发模型批次。

## 1. 核心调整与当前起点

前序方案把同一批知识先写成“唯一事实正文”审核一遍，再改写成“双语卡片”审核一遍，另单跑一轮题目映射审核，中间协议与重复写作占用了主要时间和 token。

本版将最终双语卡直接作为知识库中绑定官方原句的学习单元，主线压缩为三类模型任务：

**全量轻量需求草案 → 按主题共享官方证据直接制卡 → 合并终审（逐卡结果＋逐题盲答判题核验） → 只修失败项。**

蓝图先由全量轻量需求形成候选组织，经最终双语卡和 1,018 题逐题回查后冻结，不再先把一套脱离卡片的中间事实报告证明完美才开始写卡。

- 原始资料保留 1,019 个固定题目 ID；已排除的缺选项题 按用户决定排除，要求覆盖范围为 **1,018 题**。
- 实际账本为verified59、pending959、held1（已排除的缺选项题）。旧59条优先无损投影并校准，不默认全重抽；新索引状态与旧分析verified分开。用户已明确完全放弃旧347卡：旧正文、教学目标目录、UID和掌握度不进入新包，不再做347逐卡对齐/去向及旧进度迁移。原始资料/官方语料/59题分析继续保留。
- 正式入库新制卡0张，最终卡数N未知、未冻结；聊天演示不计正式覆盖。未发布新版内容或OTA，未做真机验收。
- 模型通道、供应商、账户与既有请求配置保持不变。当前缺全局候选规模和新流程实测单价，不能给可靠全量工期。N=450及旧5–8.5小时/165–286万token仅保留为历史情景，不能作为当前预测或支出额度。

## 2. 四项工程边界修正

1. **服务分桶只组织材料，不自动判定知识相同。**
   全库先抽完轻量需求，再按服务或主题桶聚合材料、共享官方检索上下文直接制卡。桶内必须保留部署方式、可用区与区域范围、协议、操作类型、数据规模、时延、成本和运维负担等改变选项胜负的条件；跨服务题保留组合依赖关系。全局目标只从原题需求和官方支持形成；不拿旧347卡/旧标签目录配对或补蓝图。新包分配全新UID，不能继承旧掌握度。
2. **准备阶段从轻从简，不预开发重型系统。**
   直接复用现有 `blockId`、选项编号和源文本哈希；检索请求按批一次交给现有 BM25 搜索，单次运行只构建一次索引；字形恢复仅处理有确定依据的位置。只有实际遇到定位不足或检索过慢时，才补充最小脚本。
3. **区分“纯脚本运行零模型 token”与“准备期可能产生的模型消耗”。**
   纯本地确定性脚本执行不花模型 token，但编写适配、诊断异常和必要的源区域视觉核对仍可能产生模型用量。准备耗时以 **15–20 分钟**为首轮目标，不当作已验证工期；不再默认额外追加 3 万 token 准备预算，所有可记录的模型调用统一计入当前试验或阶段额度，主对话与原生不可观测开销仍单列 `unknown`。
4. **合并终审一次读取，但分别输出两份验收结果。**
   独立 Reviewer 同时读取原题、实际 AWS 官方依据和候选双语卡，但必须分别产出：
   - **逐卡验收结果**：核查官方原句支撑、双语等义、判题提问、难度与先修，并逐卡检查可理解、可回忆、可迁移、可自评；
   - **逐题覆盖与判题支撑结果**：核查关键条件是否保留、仅凭关联卡片能否支撑关键选项判断。
   `lint-deck.mts` 只负责格式合法性；手机端实际渲染和跨服务组合验证仍须独立完成。试验中已通过且后续未发生条件或证据变更的卡片与题目结论可直接复用。

## 3. 让卡片真正帮助判断真题：制卡与终审硬规则

聊天演示暴露的重点是：提示过强、单卡捆绑多个目标、背面复读，以及综合题缺少明确自评标准。下面保留判题支持要求，并在同次终审加入可理解、可回忆、可迁移、可自评的教学检查；必要基础概念不能一律删除。

### 3.1 正面提问：明确学习目标，避免泄露待判断的答案

- 每张卡一个主要学习目标；允许必要用途、术语与机制解释，避免无关百科扩展。Easy保持短小，帮助初学者建立理解，不要求全部改成长情景题。
- 选型题不能先写出正确方案再问为何正确；机制题可以写出被研究的服务。根据目标使用业务症状、约束或条件变化，不能只靠抄题干完成作答。
- 三档难度与正面职责（沿用 `Difficulty 1/2/3` 与 `COM/RAR/LEG` 映射，不改抽卡概率或按序获取逻辑）：
  - **Easy / 1（用途回忆、机制解释）**：直接问决定选型成败的关键机制或硬限制（例如有状态与无状态、是否支持显式拒绝、备用实例能否接读）。
  - **Rare / 2（对比辨析、条件变化）**：给出决定胜负的限定条件（如最低成本、最少运维、单 AZ 可重建与多 AZ 不可丢、协议或地址限制），要求判断选谁及条件变化时如何切换。
  - **Legend / 3（组合应用）**：给出 2–3 个同时成立的约束并写明需回答几个判断点，训练多组件衔接与组合排除；组合卡依赖的基础事实必须先有 `Easy` 或 `Rare` 卡明确教授。

### 3.2 背面答案：答／考点／易错提醒三段式

沿用首行 `答：` / `Answer:` 与既有内容契约；教学文案固定为互不重复的三段。新标签的实际渲染仍在试点核验，不预先宣称零改造：

1. **`答：` / `Answer:`（条件 → 动作结论）**：直接回应问题；Easy/Rare用简短结论，Legend可列少量必须命中的要点，供翻面后自评。
2. **`考点：` / `Key point:`（核心机制或判断规则）**：提炼 AWS 官方依据支持的一条机制、条件或因果解释，不重复首句；必要术语在此用短语解释。
3. **`易错提醒：` / `Watch out:`（高频干扰项淘汰点）**：直接点明相近竞争方案输在哪个条件或限制上；没有真实混淆风险时不硬凑字数。

`SOURCE:` 附紧凑官方 URL 与 1–2 条精确支持原句（手机默认紧凑链接，短引文按需折叠）。原题文本、印刷答案、社区讨论、私有题号映射与本地路径一律留在私有审计包，通过白名单导出确保不进入公开包。

### 3.3 第一步提需求：同时抓住“决胜条件”与“竞争干扰项输点”

G-need按 [全库需求索引约定](2026-11-02-aws-needs-index-plan.md) 执行；不改原账本、不另起框架。先有可回溯规范视图，再用既有`blockId`/选项ordinal提取下列待核验输入，不写解析或宣布正确选项：
- **关键条件候选**：题干及选项中可能改变判断的限定（协议、部署类型、区域/AZ、一致性、时延、数据量、成本或运维要求）及源异常标记；
- **必要判断候选**：需要学习者判断什么，隐含先修候选另标待核验；
- **待核验差异**：易混选项之间哪些能力/限制需查证；不凭模型记忆判输赢，不展开无关陪跑项。

原题印刷答案与讨论绝不作为 AWS 事实依据；所有正选机制与干扰项淘汰理由都在第二步制卡时用实际 AWS 官方文档块核实。

### 3.4 第三步合并终审：“仅凭卡片盲答判题”门禁

- **单卡关系据实标注**：单张基础卡相对综合题仍如实标 `direct_test`、`partial` 或 `prerequisite`，不夸大单卡作用。
- **整题关联卡集必须联合闭合**：零作者历史的独立 Reviewer 读取原题完整题干与全部选项，**不看印刷答案，要求每个决定性推理定位到当前卡片的具体内容**，检查关联卡片明示的规则能否区分关键选项并解释竞争项为何出局。官方原文用于核事实，不能替卡片补上未教授知识；不声称能观测或彻底禁止模型使用自身记忆。
- **判定口径**：只要卡片仅提到服务名称而未教会决定胜负的条件或组合方式——哪怕 Reviewer 靠自身常识能猜对选项——仍判该题**覆盖不足（`FAIL`）**，打回补强对应卡片的提问/`易错提醒`或补充必要的 `Rare/Legend` 卡；原题本身印刷残缺或参数缺失者单列 `source_ambiguous`。


### 3.5 教学审查与定向修正：并入原有终审

作者与Reviewer共用 [AWS卡片教学审查规则](aws-card-teaching-review.md)。每卡私有草稿明确主目标与必要答题要点，Legend列出先修；复用现有等价字段，不给手机增加栏目。

同次逐卡审核增加U1可理解、R1可回忆、T1可迁移、S1可自评；每卡都检查，但不强迫每张都找问题。只有妨碍当前目标、关键判断或先修完整的实质缺陷需返修；措辞偏好记NOTE。事实、双语、教学和逐题覆盖的必选维度分别保留，某一维度PASS不能抵扣另一维度FAIL/必要UNKNOWN。

通过项短记结果；失败项输出稳定findingId、位置、规则、缺陷、action与影响对象，作者直接按动作修正：改正面、改背面、拆卡、补先修、补必要条件变式或修题目关系。只重审变化对象及依赖；拆补卡不重置原问题次数，新包内目标变化同步更新UID/依赖和修复谱系，不做旧卡对齐或进度迁移。Legend按mustAnswer评判必要点，等义回答可通过，不要求逐字背答案。

这是教学设计检查，不是已证明记忆或提分。规则实际接入作者/Reviewer的冻结输入并完成相关控制后，才可声称试点执行了本检查；本轮不修改执行脚本，不启动内容任务。增量调用内容计入既有预算，等待P1实测，不另设审查角色或阶段。

## 5. 失败恢复、源字形与全新身份

- **逐项落盘，只修失败项**：每批模型返回后，按单张卡、单道题独立验证并落盘；已通过项绝不随同批失败项重跑。当某张共享卡片在返修中修改了限定条件或结论时，自动失效并重审其关联题目。
- **修复上限不变**：每项最多 2 次自动修复；既有特许返修题 既有特许第 3 次修复已通过，不推广到其他项；不通过改名、重分批或换 ID 重置失败计数。
- **源字形与印刷瑕疵区分**：全书 3,389 处 `<NUL>` 仅在字体对象/字符码/字宽与冻结源位置可唯一确定回绑时脚本批量恢复，存在歧义的位置单独核对源区域并保留旁注；原书排版粘连（如吞掉句末字母）与选项缺失（如 已排除的缺选项题）分开记录，不臆测出版方本意。
- **用户范围更新：完全放弃旧卡**：旧347卡只归档，不作为正文、目标目录、UID或掌握度来源；取消逐条旧卡去向/语义对齐及旧进度迁移门禁。新UID与旧集合不相交，新包内部重试保持身份稳定、拆合保留问题谱系；验证新学习记录初始化、发布幂等与内容/缓存版本替换，不能让旧卡残留混入新包。旧线上内容/历史文件在本轮不删除，保留安全发布前备份与回滚依据。授权记录见私有执行记录中的用户范围变更授权。

## 6. 首轮试验窗口、总预算与工期估算

### 6.1 50题首轮验证窗口与停止阈值（详见专项计划）

- **时间窗口**：按准备目标 `15–20 分钟`、内容试验派发上限 `30 分钟`、汇总 `5–10 分钟`，安排一次约 **45–60 分钟**的尝试窗口；该窗口不是保证 50 题全部闭合的承诺工期。
- **Token 停止阈值**：累计可观测 token 派发上限设为 **100,000 token**（统一覆盖本轮所有可记录的模型输入、输出、推理、返修与必要诊断调用，不再默认另加 3 万准备预算）。
- **诚实停机**：达到 100,000 可观测 token 或 30 分钟内容派发上限即停止派发新调用（单条在途调用可能略超累计阈值），保存全部已完成双语卡与逐题结论，如实汇报：**多少题已有充分卡片支撑判断、多少题仍缺知识/限定/组合训练、哪些原题自身有歧义**。

### 6.2 当前成本与工期口径

G-need只按实际输入、输出、共享上下文、合并判断、校准/重抽、失败/修复及必要检索诊断记账。按Kimi每题读500/写150的示例，1018题抽取661700已含源阅读509000，不能另加同一遍40–60万；再加假设聚合5–10万为711700–761700，但尚未包含所有真实成本。59题重抽按同假设是38350，而非几千；当前优先迁移能无损复用的旧记录。详细情景见G-need约定和阶段测算文件。

先实测首批，再按剩余题数与真实候选规模估算G-need余量。全局目标/候选N及制卡单价未知时不报全量完工小时数。旧测算文件在私有执行记录中原样保留为历史N450情景，不是本版预算；教学增量也尚未测量。

规范视图可复用不等于后续模型读源免费：制卡尽量用需求短表，最终独立覆盖审核仍读原题/全部选项，按真实输入另外计。缓存和原生监督/视觉U不计成免费或零。G-need总额度尚未认可，旧50题制卡10万/30分钟阈值不授权全1018需求运行；全量B总仍未设定。未来在已认可阶段预算内无需每批确认，到限不派新调用并保存状态；当前不执行。

## 7. 当前执行边界

本轮更新主计划v5.3、G-need v1.1、50题计划v2.3及教学规则v1.1，依据用户明确要求取消旧卡复用/对齐/迁移；原版本精确归档。只进行文档/只读统计与必要独立变更审查，不生成规范化源/需求数据、不抽模型批次、不修改执行脚本、不重新初始化账本、不发布。教学审查规则继续使用，实际注入及相关控制仍待执行。正式运行保持planning_revision_hold，aws自动化PAUSED；文档审查PASS不解除暂停或批准费用。
