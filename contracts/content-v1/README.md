# Content v1 current-behavior baseline

These dummy cards contain no AWS teaching facts. `content.schema.json` documents current structures; it adds no runtime parser, dependency, or stricter import gate. Existing C#/TS canonicalizers remain authoritative for trimming, byte output, CJK, MCQ parity, and limits not expressible here. `samples/cases.json` includes accepted and rejected authoring values. The samples are read directly by backend, frontend and mobile tests.

- Authoring missing `teaching`/`tags` means retain on update; explicit null or an empty object means clear. Read responses and worker exports omit empty structured fields. Legacy unstructured cards remain valid and preserve their serialized bytes and review hash formula.
- Teaching accepts absent schema as v1, rejects an explicit unsupported schema, trims text/arrays, discards unknown properties, and preserves prerequisites plus the Chinese prose mirror. `mustAnswer` is 1–8 unique strings; prerequisites 0–16 unique stable UIDs. Chinese `mustAnswer` is not part of the current canonicalizer.
- Authoring tags allow only `domain` and `examTask`; unknown tags fail. Domain is 1–4; current import allows arbitrary task text. Mobile types/mappers preserve unknown tags from installed files. The new pure candidate validator adds official tasks only for the two AWS mapped deck slugs; legacy untagged cards remain valid, while partially tagged cards can remain drafts until publish.
- Translation v1 is zh-CN only, rejects unknown fields/version, and must mirror the English text/MCQ/front-help shape. It is distinct from the teaching Chinese mirror.
- `samples/legacy-card.bytes.json` pins actual `ContentJson.Serialize` bytes without a trailing newline. `samples/sync-event.bytes.json` pins the current mobile record/queue/push event after substituting deterministic identity/deck values. Queue ACK behavior is covered by existing sync tests, not reimplemented here.
- Manifest v2 and chunk package v1 are separate versioned envelopes. The chunk installer currently rejects unsupported package versions. Sync event schemaVersion currently defaults absent/null/nonpositive to 1 and accepts positive future versions; do not infer rejection from a version field alone.

Markdown now roundtrips `TEACHING:` and `TAGS:` JSON sections through parsing, planning and the batch import runner. Absence preserves stored structures; an explicit `null` clears them. Existing documents without either section serialize exactly as before. Mobile readers render supported teaching-v1 (including the existing schema-absent input) and fall back to ordinary explanation text for unsupported/malformed teaching, preserving the installed source file and allowed tag metadata.

Tags-only cards now append an explicit `tags-only-v1` hash payload to the review hash and publish digest. Legacy cards with neither structure and existing teaching-v1 cards retain their previous hash formula and bytes. Front-help hash behavior is unchanged. No card content or prior review receipt is rewritten.

`DeckReferenceValidation.Validate(deckSlug, completeCandidateCards)` retains the authoring canonicalization adapter from N5a. Its graph rules now live in Shared Db `CandidateDeckValidation.Validate(deckSlug, IReadOnlyList<CandidateDeckCard>)`, reused by publish and Worker without a Worker→Vpc dependency. It returns stable input/traversal-order errors capped at 100 plus `Truncated`; callers must refuse when `IsValid` is false. Include tombstones to distinguish deleted references from missing ones, or a deleted card absent from the candidate set is reported as missing. Do not call on individual import batches. The iterative DFS is O(V+E), does not recurse, and reports bounded back-edge pairs instead of unbounded cycle paths. Publish preview, ordinary dispatch, controlled dispatch inside its deck lock, and Worker before upload all validate the complete exported active set plus deleted-UID tombstones; existing snapshot/generation fences still reject later mutations. Draft import/edit paths do not invoke this gate. Migration 055 changes only protected-card revision comparison: translation/navigation/display-only changes keep revision while editing snapshots still invalidate; English/core and English teaching/prerequisite changes still increment revision. The migration performs no row/progress backfill.

Delta patches use numeric `schemaVersion: 2`, as emitted by the Worker and pinned in `samples/delta-v2.json`; package v1 is a separate envelope. The mobile installer rejects unsupported delta versions before applying deletes/updates, and rejects unsupported teaching in the resulting delta deck before publishing its temporary file. It then tries the existing chunk/full fallback. If fallback fails, prior installed bytes and build metadata remain. Previous-build teaching/tags values are retained and compared structurally, including field add/remove and same-revision display edits; JSON object property order alone does not create updates. The shared delta sample contains dummy cards only and is checked against actual Worker artifact generation and the public mobile installer. Tests can export generated bytes with `N5_DELTA_OUTPUT_DIR` and feed those exact artifacts into the mobile suite. Patch SHA verification authenticates patch bytes; it does not verify byte equality with the separately serialized full deck.
