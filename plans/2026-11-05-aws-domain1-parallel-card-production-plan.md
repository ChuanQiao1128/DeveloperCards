## 3. 并行方式：主控一人、作者与审查交错

默认最多4个活跃模型任务，包含主控：

| 角色 | 数量 | 工作与写入权限 |
| --- | ---: | --- |
| 主控 | 1 | 维护唯一队列、分配判断和题目责任、共享资料准备、运行本地检查、串行提交全局总账 |
| 作者 | 1 | 每次5–10张，只读本包冻结材料，写自己的candidate版本；不写总账，不兼任审查 |
| 独立Reviewer | 2 | 各自以全新上下文读冻结请求，逐卡七项审查并同次核对所属原题，只写本请求结果 |

作者与审查目标使用当前已用的gpt-6.1-sol/high；模型角色参考本机codex-dynamic-delivery路由。主会话不声称自动切换模型。执行前核对实际工具可用性；保持当前原生通道，不启用已暂停的CLI作者、不改供应商／密钥、不清零历史预算。平台限额出现时停止新派工并保存进度。

此处根据近期“写作约2–3分钟、首稿后约5–6分钟（含审查、封装与收尾）”的观测，把skill常规的“2作者＋1Reviewer”改为“1作者＋2Reviewer”作为首测配置；实际仍受准备与跨题依赖影响，不能据此承诺吞吐。

所有子任务使用`fork_turns: none`，只传任务包；不复制整段聊天。作者与Reviewer角色固定，不把作者Agent转成其他包的Reviewer，也不让子Agent继续派生。

**一个波次建议15–20张，拆成3–4个5张包。** 新主题或边界较多时仍取5张；同机制较稳定时可取8–10张，不能为了摊薄成本堆大卡。

典型交错：作者写A → Reviewer1审A，同时作者写B → Reviewer2审B，同时作者写C → 空出的Reviewer审C。主控在此期间做本地校验与下一包资料定位。每波卡片验收及所需题目核查完成后，主控一次累计合并，再开启下一全局基线。

如果实测作者排队而Reviewer经常空闲，可切为“主控＋2作者＋1Reviewer”；只并行无依赖题组。两种配置先测吞吐、等待及输入量，不宣称Agent越多越快或并行自然省token。

共享先修必须先有有效接受凭证。需要尚未通过的兄弟包知识时，延后该题的最终审查或移到后继波次；不能读取另一作者正在修改的卡片。每题指定唯一最终审查责任，跨包partial结果不能机械合并为充分。

## 4. 开工前只补两项必要能力

当前脚本已经支持5–10张构包、按卡失效、独立审查交接、真实Linter／导入、累计索引及共享run的锁与SHA校验。以下两项**尚未接入**，不能直接并跑现有单批命令并各自提交：

### A. 一波冻结、唯一提交

复用`pipeline.py`的多batches结构，增加小型波次准备入口：统一冻结同一基线、原题归属、目标责任、UID及证据，再生成各包作者输入。作者和Reviewer只写独立产物目录，只有主控串行运行会改`state/timings/cache`的步骤。

全波通过后主控调用一次现有`closeout.finish()`，使用现有锁、SHA比较、原子更新与回读。锁不等于自动rebase；若其他任务改了run，保留本波成果，由主控重新核对基线，不能覆盖或重派作者。一个包阻断时隔离该包及依赖，若需提交其他已通过包，明确生成新的交付集合并保留未完成项，不冒称原波次全部完成。

### B. 接受卡作为真正的题目上下文

主控／本地脚本加载相关接受卡的**完整私有正文、来源摘录、有效审查凭证和递归先修**，先校验版本与可复用性。Reviewer只接收待审卡、相关接受卡正文及先修、官方摘录、完整原题和检查规则；**旧审查凭证、旧PASS、历史结论及作者辩护均不进入Reviewer输入**。不能只靠旧PASS放行，也不能只读缺少私有评分／先修信息的公开导出。卡片版本与当前标准不兼容时，做必要定向复核，保留已核事实，避免重新写作或重搜。

指纹与失效检查覆盖两者并集；导出、新增接受数只计本批新增／实际修订卡。增加“不调用作者、只核题目”的路径，先尝试用已接受卡闭合旧缺口。例如Q359可组合现有HTTPS卡与S3客户密钥控制卡回到原题复核，是否充分由独立结果决定。

两项适配合并实施、测试与独立复核，预估45–90分钟，出现复杂遗留问题可延至2小时。并行收尾冲突、重复题目归属、来源／先修变更失效和跨批原题引用必须有针对性检查。未通过时保持串行安全路径，不能用缺失上下文的结果宣称全域覆盖。此阶段不扩建后台服务、自动rebase或另一套蓝图系统。

正文截取同时加入小保护：正文锚点必须唯一；同文不同URL按URL及正文哈希准确绑定，不再依赖人工删除冲突快照。完整来源保留，不能为减字节删必要限定。已有历史请求保持原样。

## 5. 节约token与时间的具体规则

- 先用脚本核对371题与622判断的集合、已有UID、版本及来源，模型不做机械计数或重新提取。
- 接受卡登记简短判断与条件，语义重复由同次作者／Reviewer确认；同词不代表同考点，不同限定不强行归并。一个判断有唯一制作责任，已有卡能用就不新增。
- 每波共用只读官方快照和证据ID；仅补缺证事实。作者读取对应完整摘录与原题，Reviewer读取实际所需卡、原题、规则和证据。相关条件、全部选项、异常及完整教学标准不裁剪。
- 每包一次作者、一次同次七项与题目审查；通过项简述依据。初次仍逐卡审查，不改为抽检。代表Rare的必要迁移按现有门槛保留。
- 评分只对应所问结论与原因，提醒不自动进入mustAnswer；减少纯评分问题导致返修。本轮不依赖尚未实现的“评分与题目指纹分离”来估算节省。
- 只修失败卡和真实受影响依赖，沿用policy的每UID最多2次自动修复上限及旧失败谱系。超限隔离并报告，不盲目重派或清零。
- 来源歧义沿用现有`remainingGaps`记录；无相关新证据时不反复研究同一问题。缺事实则补证，原题本身无唯一答案则给出官方支持的说明，不能靠加长卡面制造答案。
- 每波自动汇总一次：接受数、覆盖状态、缺口、计时、调用与输入大小；最终回读一次，不重复生成长报告。
- 并行不保证减少总token。近四批native token均为unknown，不能承诺具体token或费用节省。记录可观测usage；未知时用调用数、输入字节、返修数作辅助指标，不能把字节换算成已测token或把缓存称为免费。

## 6. 分段执行与何时verify

| 阶段 | 做什么 | 验证与交付 |
| --- | --- | --- |
| 起点整理，15–30分钟 | 从现有索引输出371题责任队列；恢复62卡的私有引用与可复用凭证，优先检查14题旧绑定 | 371题唯一且Q868不在范围；622判断有来源指针；不重新抽考点 |
| 最小适配，45–90分钟 | 完成上一节两项能力及正文／URL绑定保护 | 独立工具复核与针对性坏例通过；旧62卡及原始证明保持 |
| 小波次校准，约20–35分钟 | 10–20张新卡，至少含一道跨批接受卡组合题，并包含无新卡的题目复核 | 七项、迁移、完整原题、真实导入及单次累计提交；记录实际吞吐，不把旧回放速度当新生产速度 |
| 全量波次 | 依队列持续每波15–20张；够用的现有卡不再生成 | 每包同次验收，每波更新总账；知识缺口与题源问题分别统计 |
| 最终查漏，约1–2小时 | 对剩余缺口补卡或补核，核对371题／622判断的最新绑定并生成领域1阅读与导入包 | 没有漏题、漏判断、重复UID、无效先修或未核实的充分支撑；尚有阻断明确保留 |

校准波次后更新卡数与时间估算再继续，不要求每波再次请求用户确认；质量失败、额度或外部材料缺失按实际边界处理。某个波次卡片全PASS不意味着371题已验收。旧的17题当前充分结果在依赖未变化且凭证有效时复用，不为了最终报告全部重审。

## 7. 卡数、工期与停止条件

**现在无法可靠确定还要新增多少张。** 559个候选目标包含重叠、先修及条件变式；现有62卡也尚未全部与领域1必要判断建立当前有效关系。第一波优先产出可执行缺口队列，后续按新增需求及去重情况更新N，不拿“371题÷每卡几题”冒充卡数。

最近第6–9批均为5张，首次自动交付分别15.41／11.59／13.12／11.84分钟；第8批最终回读为15.33分钟，另列，不从完整耗时扣除。第8–9批首轮无返修，首稿后仍约5.3–5.7分钟，说明需要实测作者与审查交错后的效果。

并行阶段暂按**40–60张新接受卡／小时**作排程假设，包含该阶段常规准备、作者、审查、修正和合并；不是已经测得的吞吐。小波次未达此值时按实测下调，不能靠减少检查维持目标。

计时采用：起点整理＋适配＋校准实际耗时＋剩余制作耗时＋最终查漏。校准中接受的新卡计入新增N，剩余制作按`N－校准已接受新卡数`计算，不重复计卡或计时。下表是向外取整的情景区间，不是精确预算或期限承诺。

| 假设尚需新增 | 并行制作部分 | 加上起点、适配、校准、最终查漏后的暂估 |
| ---: | ---: | ---: |
| 100张 | 约1.7–2.5小时 | 约4–7小时 |
| 150张 | 约2.5–3.8小时 | 约5–9小时 |
| 200张 | 约3.3–5小时 | 约6–10小时 |

以上100／150／200只是工期情景，不是卡数预测；少量重核卡、额外题目复核、题源矛盾或工具问题会影响总工期。不可获取的原文、无法唯一化的题目没有可靠解决时限，不包括在无条件完成承诺中。

完成以当前知识卡及题目证据为准。最终若仍有源题阻断，交付具体题号、官方依据、已覆盖判断和未确定之处，不自动排除，也不宣称371题全部充分支撑。源题问题可先隔离而不阻塞其他独立题组。

本阶段由当前会话调度，支持落盘后恢复；不会自行启用aws自动化或承诺关闭应用后继续执行。本轮只生成计划和基线，不生成新卡、不改生产run。
