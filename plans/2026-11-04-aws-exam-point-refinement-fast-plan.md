# 全量考点索引增量精炼：加速方案

日期：2026-11-04 · v1.1（缩小当前阶段范围）

本方案替代[前一版全量升级计划](/Users/qc/Desktop/DeveloperCards/plans/2026-11-04-aws-full-exam-blueprint-upgrade-plan.md)的下一步安排。前一版8–12小时包含逐选项官方核验和全题独立复核。本次先完成候选考点索引的增量精炼、归并及抽检，初步预计2–4小时；两种估算范围不同，不是同等工作量的提速实测，也不能直接相加作为项目总工期。

本轮仅修订计划，未启动全量内容任务。

## 当前先交付什么

利用现有1,018题/4,209选项、1,697父判断和1,532候选目标，整理每题的三项核心内容：

| 字段 | 要求 |
| --- | --- |
| 核心考点 | 明确本题要区分或完成什么判断，避免只列服务名或泛泛的“如何判断” |
| 决定条件 | 保留改变判断的限定、数值及组合；绑定原题位置 |
| 所需知识范围 | 指出涉及的机制和竞争边界，供后续共享核验及制卡，不冒充已经核实的技术结论 |

例如Q282：核心考点是“用目标端来源限制防止绕过ALB”；决定条件是“仅允许ALB，并排除子网内外其他来源”；知识范围是“来源安全组引用、关联安全组许可合并、可达性与准入的区别”。

一题可以涉及多个必要考点，但不把每个术语或配置动作拆成独立目标。通常用简短结构化字段表达，复杂题允许更长；完整原文及全部选项继续保留，不靠删条件压缩。

当前不写长题解、不逐选项给技术判定、不研究所有AWS能力、不生成双语卡，也不认证唯一正确答案。既有经过核对的官方证据和来源限制照原范围保留；新增技术事实留待后续核验，不能直接当作卡片答案。

## 加速的具体做法

1. **先查缺口，再做增量处理。** 脚本从旧目标、需求、映射和异常生成差异清单；模型重点处理目标过宽、重复分裂、条件混杂、只有服务名、来源未审或归并不确定的部分。已清楚的候选保留，不逐题重新写一遍。
2. **精简模型输入输出。** 只提供当前题所需的候选字段，元数据和ID绑定由脚本完成；需要语义改写、归并或抽检时，仍读完整题干和全部选项。不反复喂旧目标的长嵌套历史，不写重复报告。
3. **按主题批处理。** 通常每批30–50题作为参考，实际以完整输入字节数、输出量和语义复杂度限批。超限就缩批，不截断原文。沿用单作者和现有通道，不以多作者并发增加重复上下文。
4. **复用既有归并，定向审新决定。** 脚本检索近邻，模型只判断新发现或受修改影响的重复。全部新合并、拆分保留依据并独立复核；未决近邻暂分开。不同条件可能改选的考点保留条件变式。
5. **按风险复核。** 未审需求、来源异常、宽目标、新增跨服务组合或可能丢条件的改写进入全审集合。来源未审265题与异常候选109题等集合先求并集，不能直接相加。普通题按固定种子分层抽检10%，兼顾主题、批次和目标类型；发现系统性遗漏就扩大相应批次或类别复核。
6. **减少重复核验。** 当前先判断考点范围，后续按归并后的知识共享官方证据。正式卡片的事实、教学和全部原题判题支撑门禁继续执行；事实核验是后移并复用，不是取消。

继承已有审查只适用于原文、目标含义、条件、关系和相应验收规则均未变的内容。新增标准未覆盖的部分不能沿旧PASS。原265条未审需求继续保持candidate；普通题抽检通过不能使未审条目逐项PASS。

## 时间估算

| 步骤 | 初步预计 |
| --- | --- |
| 本地索引、差异及风险筛选 | 10–20分钟 |
| 首50题试跑与抽检 | 15–25分钟 |
| 剩余968题的增量精炼 | 55–110分钟 |
| 跨批归并、风险复核与抽检补查 | 25–60分钟 |
| 全量映射检查与导出 | 10–20分钟 |
| 合计 | 115–235分钟，排期约2–4小时 |

这是缩小范围后的待实测预测。尤其“剩余968题55–110分钟”依赖已有目标的大量复用、紧凑输出及较少新增争议归并；不能当成已验证速度。若差异/高风险集合或新合并数量超预期，需上调预测。

首50题包含5个既有样例和45个新增处理样本；“新增”指本轮处理工作，这45题原本已有候选目标，并非尚无需求映射。复用、语义改写、归并和独立复核分别计时记量，不能用旧样例回放速度推算其余题。首50题及累计100题后按实际剩余工作类型重新估计，不只看每题平均耗时。

旧候选需求阶段约190分钟只能提供历史量级参考，不能证明本方案时间。先前8–12小时也不是本轻量阶段已发生的耗时。原模型通道、预算、用量及问题次数均不重置；本轮无作者CLI/API调用，原生用量仍不可观测。

## 产物与验收边界

执行时在RUN/exam-point-refinement-20261104/生成：

- questions.exam-points.jsonl：精确覆盖1,018题，每题列三项核心内容和源引用、当前审查状态。
- refined-blueprint.json：共享知识范围、考点、条件变式、题目映射与旧目标去向；不冻结卡数。
- review-and-coverage.json：全量结构/集合检查、已审和未审范围、新合并依据、风险复核、抽检及异常清单。
- 项目reports中的可读Markdown，由脚本生成，不再人工撰写全库长报告。

全量脚本检查必须核对题目/选项精确集合、条件及原目标去向、双向引用和状态统计。结构完整只证明可追溯与无漏项，不证明技术事实或全部语义正确。

交付时分别报告继承候选、已精炼未独审、独立复核和抽检数量。称为“全量考点候选索引已精炼”，不能称“1,018题已逐题事实验收”或“所有考点可直接制卡”。既有题源矛盾照常保留；已审和待审集合均可用于下一阶段组织检索，但只有经过后续正式门禁的技术内容可进入卡片。
