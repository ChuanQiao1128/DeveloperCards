# 按考试领域组织现有考点，形成可跨题复用的制卡单元

日期：2026-11-04。范围：方案与现有关系示例；不重新提取考点、不重新分类原题、不生成卡片。

## 目标与已有基础

最终按四大考试领域逐批优化和制卡，使一个完整知识判断能够反复用于多道原题。学习单元保持可理解、可回忆的粒度；不靠增加卡片长度或重复收录同一内容来增加题目关联数。

现有蓝图已经有objectiveId、qids、needRefs、conditions、variants、compositionRefs和verificationTopicIds。因此考点与原题的关系已有基础，本次补充考试领域视图与教学组织，不建立第二套考点库。

本轮只读统计：1,532个候选目标中，339个已关联多题，1,193个仅关联一题；按来源题的主领域计，94个目标的来源题横跨两到三个主领域。这不是最终卡数或已验证的卡片覆盖数，也不等于只有94个目标需要跨领域引用。

四领域分类来源沿用既有CSV：原表1,019题，制卡范围排除Q868后1,018题全部可关联。只使用主领域、主任务、跨领域任务和分类状态；待核事项保留状态与来源引用，其中含建议答案的文字不能混入制卡知识输入。答案列不作AWS事实依据，学习状态快照不迁入新包。

## 1．先把现有关系接入四领域视图

学习导航采用：**领域 → 官方任务 → 现有考点／轻量共享分组 → 卡片 → 原题及必要判断。**

全部视图使用现有ID和引用，正文只保存一份：

| 层次 | 已有内容如何复用 | 要补的内容 |
| --- | --- | --- |
| 原题 | questionRef／qid、原题条件、选项ordinal、既有需求 | 关联CSV的主领域、主任务、交叉任务及待核实标记 |
| 考点 | objectiveId、goal／scope、needRefs、条件与变式 | 生成涉及领域的候选视图；仅在制卡排期需要时确认主归 |
| 共享分组 | 默认直接使用现有目标 | 只有确认多个目标是同一机制和可迁移判断规则时，登记稀疏归并决定及原目标ID |
| 卡片 | 后续实际创建的全新卡片UID及正文 | 绑定来源目标、支持的具体needRefs和适用条件 |
| 原题回检 | 复用原题全部必要判断 | 依据实际卡面确认哪些判断被支持、整题还缺哪些内容 |

题目层的主领域直接沿用既有分类；知识点层按本目标实际训练的判断确定归属。整题的所有交叉标签不能不加区分地复制到它关联的每个考点。

例如Q456整题同时涉及弹性和成本，但“EC2恢复涉及哪些配置与数据”这个共享目标主要解决恢复完整性，不能仅因Q456有4.2标签就认定该目标已完成成本考点分类。

脚本先产生领域候选视图和来源支持清单，保留跨领域引用。无需在开始制卡前重新语义裁决全部1,532目标的唯一主归；实际主归及边界在各领域优化批次确认，仍不确定时明确待定。

## 2．多题复用通过既有判断关系来证明

沿用needRefs、conditionRefs和variants说明每个考点作用于原题的哪一步，不为全库再填写一套重复的“题目目标／关键条件”。仅当现有引用不能解释作用时，补一条局部支持说明。

识别共享的依据是相同机制和可迁移的判断规则。相同服务名、相似措辞或相同答案字母均不足以证明可以共用一张卡；允许不同条件对应不同结论，相关条件变化须保留。

优先检查已有339个多题目标，区分共同必要判断、先修、宽泛主题关联。对1,193个单题目标，只通过本地近邻检索提出潜在共享对；确认新归并时才做语义判断，不重新抽取所有目标。

确实独有的限制、不同机制和综合整合目标继续保留。每个原目标都保留去向；不能为提高“每卡关联题数”删掉独有考点或制造宽卡。

共享单元默认就是一个现有目标；必要时用轻量分组引用多个目标。它最终可能是一张完整判断卡，或很小的先修与应用卡组，数量由理解和记忆负担决定。

## 4．逐领域优化与制卡

先生成四领域及任务的导航，然后按领域逐批推进；可优先从领域1开始。每批处理一组可界定的共同判断，不要求先完成全库重新分组或建立庞大的中间知识库。

1. 沿既有原题和目标确认本批真正需要的判断、共享范围及领域归属，保留每题的特有条件。
2. 按共享机制核验AWS官方证据；来源歧义、事实未决与已支持内容分开，重复研究按适用范围复用。
3. 设计少量完整判断卡并检查理解与回忆负担，复用已有生成入口，不将一个目标机械定为一张卡。
4. 对全部关联题逐项回检必要判断；综合题需要多个单元联合支撑，缺一个必要判断仍保持未闭合。
5. 只修缺口与受影响项，更新域内及跨域引用，共享正文和身份不复制。

四领域是组织和制卡视图。共享卡只生成一个内容实体和UID，不因出现在不同领域创建多份内容或多份掌握度。若现有客户端只支持单一目录，则采用一个主归目录及交叉引用／标签，具体呈现能力在实现时检查，不预先宣称前端已支持多目录共享。

## 5．真正衡量“学少量知识，解决多题”

分开统计以下结果：

- 原始关联题数：说明潜在复用范围，不代表整题可解。
- 共同必要判断的支撑数：当前卡面明确支持了哪些needRefs；正式direct_test／prerequisite／partial需按真实内容确认，当前关系仍为候选。
- 小卡组完整支撑的独立原题数：全部必要判断及条件已闭合；来源有歧义的题继续单列。
- 实际迁移与记忆效果：通过学习者对不同情景的作答验证；已公开答案的重复作答不作未见测试。

优先做共享必要判断明确、证据可用且能保持短小的单元；综合题完整支撑及记忆负担共同决定价值，不能只按关联题数排序。重复题与相似变体分别保留来源，统计迁移效果时区分不同题号和不同情景，避免重复题虚增收益。
