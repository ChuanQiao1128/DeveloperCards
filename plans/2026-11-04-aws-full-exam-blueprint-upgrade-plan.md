日期：2026-11-04（Pacific/Auckland） · v1.0

本轮交付执行计划和时间估算，尚未启动全量模型批次。下一阶段先升级考点蓝图，再继续制卡。本计划更新主计划v5.3中“候选蓝图后直接进入制卡”的阶段安排；新卡包、官方依据、原题范围和历史保留规则继续有效。

## 目标与范围

把现有“需要判断什么”的候选目标，升级为能够指导制卡的考点：**在什么条件下，依靠什么机制，作出什么判断，为什么能区分题目中的方案。**

- 覆盖原范围1,018题及4,209选项，Q868继续排除。使用规范源的稳定questionRef及选项ordinal识别题目，不依赖可能重复的印刷题号。
- 复用原需求、候选目标、条件变式、题目映射、官方语料和已有合格证据；不重新提取PDF，不重写已确认且本次规则仍适用的结论。
- AWS技术事实只以官方依据核验；印刷答案和社区投票不进入判题依据。旧347卡正文、目标目录、UID和学习进度继续排除，旧15张接受卡也不作为事实来源替代官方原文。
- 形成每题的实质考点分析，再归并共同机制与同类判断。保留会改变选择的条件、跨服务组合和必要先修关系。
- 本阶段不生成正式卡、不冻结卡数、不发布、不恢复aws自动化；现有15张接受卡、25个唯一UID及0/50题卡支撑状态均保持。

## 执行步骤

### A．准备输入与最小适配：30–45分钟

固定规范源、需求、蓝图和规则版本。用本地脚本构建“题目—候选目标—待核主题—官方候选”的索引，生成断点清单和批次输入；复用现有检索、运行锁、用量日志和校验工具，不新建编排框架。

现有tools/aws_cards/pipeline.py面向卡片契约，本阶段仅复用适用的公共能力；为考点分析补最小输入输出适配，不硬套卡片schema，也不改生产制卡入口的行为。确定性检索、去重、哈希、统计和Markdown渲染由脚本完成。

### B．首20题校准：25–40分钟

包含现有5题和15道新增题。新增样本兼顾不同主题、跨服务组合、近似题、条件变化和来源风险，避免只选容易题。复用既有有效事实及结论，不重新写5篇长报告。

这一批验证：知识与考点是否分清、能否解释全部选项、归并是否丢条件、结构化输出是否可直接用于下一步制卡。用一组保留真实条件的样本，以及隔离副本中的缺条件/错合并坏例检查门禁；不得改真实数据。

复用的5题与新增15题分别统计耗时和用量。全量预测按新增题速度及真实可复用比例加权，不把旧题回放速度当新增题吞吐。

达到质量要求后按同一流程继续。先记录首20题的准备、检索、模型、审查、修复、保存时间及用量，更新全量预测；累计100题后再更新一次。通过的内容只在相关输入或规则改变时重做。

### C．处理剩余998题：预计5.5–8小时

按现有主题和相邻考点分组。一般每批10–20题，同时受输入字节数和输出预算约束；超过上限就减批或分阶段处理，不截断题干、选项、条件或必要引文。

每批只做一次主要语义生成：读取完整原题/选项、必要候选信息和共享官方摘录，产出考点、知识机制、选项依据及异常。同批独立核对事实应用、必要性、选项解释和源问题；不再分别写长解析、通用事实报告、教学报告再多轮改写。

沿用单个主作者顺序推进，确有必要的独立审查使用fork_turns:none的最小输入。审查期间可以本地准备下一批资料，不派多个携带完整上下文的作者。全部1,018题都要有本轮有效审查记录；旧需求阶段抽查不能抵扣。

官方检索按机制共享：先检索本地语料及已保存的官方快照，证据不足或有时效问题再定向读取官方页面。一次取得的同范围证据可以用于多题，逐条保留绑定；不把同服务名当作知识相同。

**每题固定内容：**

1. 原题目标与决定性条件，保留源位置。
2. 本题真正考查的一个或少量完整判断；综合题保留必要组合。
3. 必要知识机制及“条件→判断→原因”；区分必要知识、支持性解释与背景。
4. 全部选项的简短判定理由，关联条件及官方主张；有歧义时说明判定范围。
5. 关联的共享知识/考点、来源限制、证据缺口及原候选目标去向。

输出写成紧凑数据，不逐题重复背景和官方长引文，不为限制字数删除必要内容。

### D．全库归并和制卡目标组织：45–75分钟

归并在各批处理中持续进行，最后专门处理跨批近邻与边界，不等全库结束才开始查重。

- 共同机制可以共享；只有同类条件下使用同一判断依据的考点才归并。保存条件变式，不能把会导致不同选择的限制抹掉。
- 同主题、相似措辞、相同答案字母都不是充分合并依据。跨服务题保留组合及先修关系。
- 如Q456/Q508共享跨Region复制机制，但Q508的异地恢复点时效仍单独保留。
- 每个旧父判断、候选目标和待核问题都登记去向：保留、归并、改作背景、拆分、重复核验或来源问题；不给无依据的删除开口。
- 对实际提出的合并/拆分做独立复核。未决近邻保持分开，不声称穷尽所有两两比较或得到最少考点数。

产出可供后续作者使用的学习目标：要教会的完整判断、适用条件、必要先修、对应题目与证据。此时仍不按“一题一张”或“一考点一张”冻结N，也不强制使用原蓝图的Easy/Rare/Legend建议。

### E．验收、定向修复与回读：45–75分钟

本地脚本检查精确题目集合及全部4,209选项、来源引用、双向映射、旧目标去向和各状态数量。审查确认不能仅把“如何判断”原样搬进新蓝图；关键知识必须形成有依据的机制与判断结论。

只修失败条目及受影响的关联项，每项最多2次自动修复；继承已存在的问题与次数，不通过改名或重分批清零。没有核对过的必要事实不能因多数规则通过而放行。

## 不确定性与完成口径

每个考点分别记录证据状态和来源状态：

- **supported**：必要技术主张有官方原句，选项解释和条件经本轮核对，可进入制卡准备。
- **evidence_pending**：必要事实缺证据，保留实际检索记录、具体缺口和下一步；对应知识暂不进入已确认的制卡输入。
- **source_ambiguous / wording_limited / scope_limited**：记录题源矛盾或条件化解读；可独立成立的知识按真实范围保留，不冒称整题有唯一解。

“全量考点已分析”要求1,018题都完成实质分析和状态复核，不能用空壳、笼统待核或仅列问题凑数。必要证据待补须有实际查询/核验记录，不能为赶时间批量标unknown。

“全量蓝图已分析”与“全部考点可制卡”分别计数；仍有必要证据未闭合时，不宣称全部可制卡。Q324一类题可以完成问题识别和知识范围分析，同时保持唯一答案未决。原始题目及总分母保持。

验收还要分别报告：已分析题数、本轮审查题数、证据通过考点数、条件化/题源异常题数、待证事实数、已确认共享机制数和实际归并数。五个产物及当前规则、输入、证据、审查版本一致，才完成本轮交付；不升级原题旧verified账本、正式卡数或最终题卡覆盖。

## 时间估算与修正方式

**初始排期：8–12小时有效执行时间。证据缺口、源矛盾或返修明显多于预期时，预留12–16小时。** 这是当前信息下的预测，不是新流程已实测吞吐；不含双语卡片制作、手机验收、发布和OTA，也不含强行为歧义原题认证唯一答案。

| 阶段 | 预计时间 |
| --- | --- |
| 准备与最小适配 | 30–45分钟 |
| 首20题校准 | 25–40分钟 |
| 剩余998题（共享取证、分析、逐题独立核对） | 5.5–8小时 |
| 跨批归并与学习目标组织 | 45–75分钟 |
| 最终验收与定向修复 | 45–75分钟 |
| 合计取整 | 约8–12小时 |

估算依据与边界：

- 旧剩余918题需求抽取的含收尾历史记录约190.48分钟，但那一轮交付的是候选需求，且没有全题事实核验与语义通过。不能把这个速度直接当新阶段吞吐。
- 旧候选目标聚合从首次派发至completedUtc约336.1分钟；旧报告324.3分钟是较早渲染快照，不相加。新阶段复用这些归并结果，不再完整重跑旧工作。
- 本计划假设剩余题约为50个“20题等效批”，平均每批6.6–9.6分钟，已含共享取证、作者和独立核对；该数值是排期假设，需首20题实测验证。实际10题批需按题数归一化，不能以缩小批量伪造提速。
- 8–12小时包含直接决定选项的必要官方核验。1,566个候选待核主题先筛必要性，不承诺把所有背景扩展为完整AWS百科研究；真有必要的证据缺口不能省略。
- 现有5题分析、聊天示范以及本地格式回放都不能作为新批量流程的每题实测时长。官方候选URL不是已验事实，不能靠计算URL数量宣称核验时间为零。

运行时采用：T剩余 = 准备未完时间 + 剩余等效批数×已完成批次中位耗时 + 未决取证/归并/终审估计。保留慢批分布和待核队列，不能只拿最快一批推全库。首20题和累计100题后更新区间；发现预测越界即汇报原因与新估算，不通过降验收标准维持旧数字。

计时覆盖准备、检索、模型、审查等待、修复、封装和回读。CLI input/output、cached输入和推理按既有口径记账，原生监督/审查用量不可观测则记unknown。时长估算不构成费用上限或新预算授权；旧试点10万token/30分钟窗口不能当作本阶段全量额度。保留原账本、原问题谱系及现有限额，不通过拆批重置。全量新增token单价在首20题后给出实测预测。

## 执行顺序和当前状态

依赖顺序为：输入与规则固定 → 校准 → 按主题取证并完成逐题考点 → 归并复核 → 全库回读。实际执行沿用当前模型通道和项目记录，不创建新任务、自动化或新服务。

本轮为规划交付，当前完整蓝图仍是候选版；全量升级未开始，第一步为A阶段输入/规则固定与最小适配。本计划不代表已完成升级、已确定卡数或已验证学习效果。
